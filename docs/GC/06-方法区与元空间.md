# 方法区与元空间

> 方法区是 JVM 规范定义的"逻辑区域"，存类的元信息；其物理实现从「永久代」演进为「元空间」。

## 方法区存什么
1. 已加载类的信息（类名、字段、方法、字节码）
2. 静态变量（static 字段）
3. 常量（final）与运行时常量池
4. JIT 编译后的代码缓存

## 物理实现的演进

| 版本 | 物理实现 | 位置 |
| --- | --- | --- |
| Java 7 及以前 | 永久代 PermGen | 堆内（受堆大小限制） |
| Java 8 起 | 元空间 Metaspace | 本地内存（默认无上限，受物理内存限制） |

### 永久代的问题
1. 回收效率低（与老年代 GC 捆绑）
2. 受堆大小限制（`-XX:MaxPermSize`），易 `PermGen OOM`

### 元空间
- 移到本地内存，默认只受物理内存限制，可用 `-XX:MaxMetaspaceSize` 限制。
- 溢出异常：`OutOfMemoryError: Metaspace`（而非 PermGen）。

## 运行时常量池 vs 字符串常量池
- 运行时常量池：class 文件常量池的运行时表示，在方法区。
- 字符串常量池：`String.intern()` 的结果，**Java 7 起移入堆**。

## 方法区会被 GC 吗
会，但很少：主要回收**废弃的常量**和**不再使用的类**。类的卸载条件苛刻（类的所有实例已回收、类加载器已回收、Class 对象无引用）。

## 何时会 OOM
- 动态生成类过多（CGLIB、动态代理、反射）→ 元空间溢出。
- 大量 `intern()` 字符串（Java 7 前在永久代）。

```java
// 触发元空间 OOM 的思路：无限生成动态类
// 配合 -XX:MaxMetaspaceSize=10m 观察
// while (true) {
//     Enhancer enhancer = new Enhancer();  // CGLIB 动态代理
//     enhancer.setSuperclass(Object.class);
//     enhancer.setUseCache(false);
//     enhancer.create();                    // 每次生成一个新类
// }
```
