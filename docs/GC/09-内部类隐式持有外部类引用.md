# 内部类隐式持有外部类引用

> 非静态内部类必须依附于外部类实例才能创建，因此编译器会给它注入一个指向外部类的引用 `this$0`；静态内部类则没有。

## 为什么会有 this$0

为了非静态内部类能访问外部类成员，编译器通过在构造函数中注入外部类参数来实现这一机制。

## 源码 vs 字节码

源代码：

```java
class MyActivity {
    private Listener listener = new MyListener();

    class MyListener implements Listener {
        void onEvent() {
            updateUI(); // 直接访问外部类方法
        }
    }
}
```

编译后的字节码（反编译）：

```java
class MyActivity {
    private Listener listener = new MyListener(this); // 自动传入 this

    class MyListener implements Listener {
        private MyActivity this$0; // 编译器生成的字段

        // 编译器生成的构造函数
        MyListener(MyActivity outer) {
            this.this$0 = outer;
        }

        void onEvent() {
            this.this$0.updateUI(); // 通过引用调用
        }
    }
}
```

## 关键结论

1. **非静态内部类 / 匿名内部类**：隐式持有 `this$0 = 外部类实例`。
2. **静态内部类**：`static` 修饰，**不持有**外部类引用。

## 为什么会导致内存泄漏

`this$0` 是一条隐式的**强引用**。当内部类对象被长生命周期宿主（线程、Handler、单例、静态集合）持有时，这条引用会让外部类始终从 GC Roots 可达，从而无法回收。

- 可达性原理见 [01-对象存活判定与GC Roots](01-对象存活判定与GC Roots.md)
- 具体泄漏场景与「静态内部类 + 弱引用」的解法见 [07-内存泄漏](07-内存泄漏.md)
