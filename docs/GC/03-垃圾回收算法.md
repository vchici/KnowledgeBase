# 垃圾回收算法

> 回收算法是 GC 的底层机制：标记-清除、标记-复制、标记-整理，三者各有取舍；现代 JVM 用**分代**把它们组合起来。

## 标记-清除 Mark-Sweep
- 先标记存活对象，再统一清除未标记对象。
- 缺点：**产生内存碎片**，且效率不稳定。

## 标记-复制 Mark-Copy
- 把内存分两块，只在一块分配；回收时把存活对象复制到另一块，再整体清空原块。
- 优点：无碎片、简单高效。
- 缺点：**浪费一半内存**；存活对象多时复制成本高。
- 用于**新生代**（存活对象少，复制成本低）。

## 标记-整理 Mark-Compact
- 标记后，把存活对象向一端移动，然后清理边界外的内存。
- 优点：无碎片。
- 缺点：移动对象需要 STW，且更新引用成本高。
- 用于**老年代**（存活对象多）。

## 分代收集理论（现代 JVM 的组合拳）
基于两条经验假设：
1. **弱分代假说**：绝大多数对象朝生夕死 → 新生代用「标记-复制」，快速回收。
2. **强分代假说**：熬过多次 GC 的对象更长寿 → 老年代用「标记-整理」，少回收。
3. **跨代引用假说**：老年代引用新生代的情况极少 → 用「记忆集」记录，避免每次扫描整个老年代。

## 三算法对比

| 算法 | 碎片 | 空间开销 | 适用 |
| --- | --- | --- | --- |
| 标记-清除 | 有 | 无 | CMS 并发清除阶段 |
| 标记-复制 | 无 | 双倍 | 新生代 |
| 标记-整理 | 无 | 无 | 老年代 |
