# 四种引用类型

> 引用强度决定对象何时被回收：强 > 软 > 弱 > 虚。除了强引用，其余都要借助 `Reference` 子类。

## 强引用 Strong
- 最普通的 `Object o = new Object()`，只要引用在，永不回收。
- **内存泄漏的元凶**。

## 软引用 Soft
- `SoftReference`：内存**不足时**才回收。
- 用途：缓存，适合"能丢但不舍得丢"的数据。

```java
SoftReference<byte[]> ref = new SoftReference<>(new byte[1024 * 1024]);
byte[] data = ref.get();   // 内存充足时能拿到；不足时可能为 null
```

## 弱引用 Weak
- `WeakReference`：**下一次 GC** 就回收，不管内存是否充足。
- 用途：`WeakHashMap`、监听器、ThreadLocal 的 key。

```java
WeakReference<Object> ref = new WeakReference<>(new Object());
System.gc();               // 触发 GC 后
ref.get();                 // → null
```

### WeakHashMap
HashMap：Entry强引用key，只要entry还在map中，key对象永远不会被GC
WeakHashMap：map内部用WeakReference包裹key，一旦 key 无强引用，entry 自动被清理：

```java
WeakHashMap<Key, Value> cache = new WeakHashMap<>();
cache.put(key, data);
key = null;                // key 无强引用 → 下次 GC 后 entry 消失
```

## 虚引用 Phantom
弱引用仍然是引用，它的价值时不阻止GC。虚引用`PhantomReference`不参与对象生命周期管理，**无法通过 get() 拿到对象**，只负责生命周期结束的回调，是一个死亡监听器。
- 用途：管理直接内存（如 NIO 的 `DirectByteBuffer` 回收通知）。

## 引用队列 ReferenceQueue
软/弱/虚引用构造时都可绑定一个队列；对象被回收后，引用对象被加入队列，便于做清理工作。

## 一张表总结

| 引用类型 | 回收时机 | 典型用途 |
| --- | --- | --- |
| 强引用 | 永不（除非断开） | 普通对象 |
| 软引用 | 内存不足时 | 缓存 |
| 弱引用 | 下一次 GC | WeakHashMap、监听器 |
| 虚引用 | 回收后通知 | 直接内存管理 |

## 与内存泄漏的关系
- 强引用持有"短生命周期对象" → 泄漏。
- 改用弱引用/软引用可让对象在无强引用时被回收 → 修复泄漏（详见 [07-内存泄漏](07-内存泄漏.md)）。
