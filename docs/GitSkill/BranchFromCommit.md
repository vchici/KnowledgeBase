# 从某笔提交新建分支，且不影响当前分支

## 核心命令

```bash
git switch -c <新分支名> <提交hash>
```

等价写法：

```bash
git branch <新分支名> <hash>   # 只建指针，不切换
git switch <新分支名>
```

`switch -c` 只做两件事：在 `hash` 处新建一个分支指针、把 HEAD 移过去。当前分支的指针和提交历史都不动——不会被“重置”到 hash。

```
        A（当前分支）──●──●   ← A 的指针不动
       /
●──●──●  ← 从这笔提交（hash）长出新分支
        ↑ B（新分支）
```

## 关键前提：未提交的修改不属于任何分支

工作区的修改不属于分支，属于工作区本身。切分支时 Git 会尝试把它们“随身带走”：

- 目标提交与当前分支在这些文件上内容一致 → 静默带过去，切回来时也还在
- 内容不一致（或目标提交里有同名的未跟踪文件）→ 直接报错中止，工作区原样不动，不会丢东西

所以“切过去再切回来，修改还在”在简单场景下能成立，但一旦你在新分支上把改动提交了，或者两边文件版本不同，就会翻车。要保证两边互不干扰，必须显式隔离。

## 三种做法对比

| 做法 | 当前分支的改动 | 新分支工作区 | 切回当前分支后 |
|------|--------|--------|--------|
| 直接 `switch -c`（随身带走） | 被带到新分支工作区 | 能看到这些未提交改动 | 没在新分支提交才会带回来；提交了就没了 |
| 先 stash 再切 | 收进 stash 栈 | 干净 | `stash pop` 还原 |
| worktree 另开目录 | 原地完全不动 | 干净（在另一个目录） | 根本不用切 |

## 方案一：stash 兜底（最常用）

```bash
git stash push -u -m "wip: 当前分支半成品"   # -u 连未跟踪文件一起收走
git switch -c <新分支> <hash>

# ……在新分支上干活、提交、push……

git switch <当前分支>
git stash pop            # 还原修改（原来的“已暂存”会变成未暂存）
git stash pop --index    # 需要连暂存状态一起还原时用 --index
```

- stash 是仓库级的栈，跨分支可见，所以在哪个分支 `pop` 都行；但建议切回原分支再 `pop`，避免改动落到新分支
- 更多用法见 [Stash](./Stash.md)

要不要加 `--index`，判断标准是：**stash 之前有没有精细的暂存状态值得保留**。

- 只是顺手 `add` 过几个文件 → 不用加，`pop` 回来重新 `add` 即可，文件内容不会丢，只是状态退回未暂存
- 用 `git add -p` 精心挑过部分改动、准备拆成几次提交 → 加 `--index`，否则挑过的选择全没了，得重挑
- 本来就是全未暂存 → 加不加完全没区别
- `--index` 要多重建一次暂存区，比默认更容易冲突；失败时命令中止、这条 stash 不会被删除，手动解完冲突再处理

拿不准时先 `apply` 验证，成功再删：

```bash
git stash apply --index   # 失败或结果不对，stash 还在，可反复重试
git stash drop            # 确认无误后再删记录
```

`pop` 就等于 `apply` + 成功后立刻 `drop`，图省事但少了一次后悔的机会。

## 方案二：worktree（两个目录并行，彻底隔离）

不想来回切换、也不想惊动当前工作区，直接给这笔提交另开一个工作目录：

```bash
git worktree add ../hotfix -b <新分支> <hash>   # 在 ../hotfix 目录检出，分支新建
cd ../hotfix                                    # 进去干活，原目录纹丝不动

git worktree list               # 看所有工作目录
git worktree remove ../hotfix   # 用完后删掉
```

- 两个目录共享同一个 `.git` 仓库（提交、分支、stash 都共享），但工作区、暂存区各自独立
- 当前目录的分支、未提交改动、编辑器里未保存的状态全都不受影响，最贴合“完全不影响当前分支”的需求
- 同一个分支不能被两个工作目录同时检出，所以新目录必须用 `-b` 建个新分支

## 只看不改：分离 HEAD

只想去那笔提交上看看代码，不准备改动：

```bash
git switch --detach <hash>
```

HEAD 直接指向该提交、不挂任何分支，看完 `git switch <原分支>` 回来。注意分离状态下新产生的提交不属于任何分支，容易被丢，见 [Switch](./Switch.md)。

## 常见坑

- 别和 `reset` 搞混：`switch -c` 是“从旧提交长出新分支”，当前分支不动；`reset` 是把当前分支指针往回挪，见 [Reset](./Reset.md)
- 新分支只包含 hash 及更早的提交，hash 之后的提交不会自动跟过来；确实需要就 `cherry-pick`，见 [CherryPick](./CherryPick.md)
- hash 可用短 hash（前 7 位）或 `HEAD~3` 这类相对写法，先用 [Log](./Log.md) 或 `git log --oneline` 查
- 直接切换被拒（`Your local changes would be overwritten by...`）不是故障，是 Git 在保护你的修改，改走 stash 或 worktree
- 分支建错或建完不想要，删除走 `git branch -d/-D`，见 [Branch](./Branch.md#删除本地分支)
