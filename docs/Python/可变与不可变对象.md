Python 里所有对象分两类：**可变（mutable）** 和 **不可变（immutable）**。这条线串起了赋值、传参、哈希、性能等一连串行为，是理解 Python 内存模型的关键。

# 谁可变、谁不可变

| 类型 | 可变性 | 说明 |
| --- | --- | --- |
| `int` / `float` / `bool` | 不可变 | 数字 |
| `str` / `bytes` | 不可变 | 字符串、字节串 |
| `tuple` / `frozenset` | 不可变 | 元组、冻结集合 |
| `list` / `set` / `dict` | 可变 | 列表、集合、字典 |
| 自定义对象（默认） | 可变 | 属性可随时改 |

判断依据很简单：**能不能在不改变 id 的前提下修改其内容**。可变对象能原地改；不可变对象一旦创建就不能改，「修改」其实是造了个新对象。

# 1. id() 与原地修改

`id(obj)` 返回对象的内存地址（可近似看作身份标识）。观察同一个变量「修改」前后 id 是否变化：

```python-run
# 不可变对象：改的是「绑定」，造了新对象
x = "hello"
print("str 修改前 id:", id(x))
x = x + " world"
print("str 修改后 id:", id(x), "→ id 变了，是新建的对象")

# 可变对象：原地改，id 不变
lst = [1, 2, 3]
print("list 修改前 id:", id(lst))
lst.append(4)
print("list 修改后 id:", id(lst), "→ id 没变，原地修改")
```

# 2. 不可变对象的「假修改」

对不可变对象做 `+=`、拼接、`replace` 等，返回的都是**新对象**，原对象不变：

```python-run
s = "abc"
s2 = s.replace("a", "z")
print("原字符串 s:", s)   # 仍是 "abc"
print("新字符串 s2:", s2)  # "zbc"

t = (1, 2)
t += (3,)                  # 实际是 t = t + (3,)，重新绑定
print("tuple:", t)
```

# 3. 可变对象真正的「原地修改」

list/set/dict 的很多方法直接改自身，返回 `None`，别把返回值又赋回去：

```python-run
lst = [3, 1, 2]
ret = lst.sort()          # sort 原地排序，返回 None
print("sort 返回值:", ret)
print("lst 本身:", lst)   # 已排序

# ❌ 常见错误：把 None 赋回给变量
# lst = lst.append(4)     # 这样 lst 会变成 None
```

# 4. 赋值是「共享引用」，不是复制

`a = b` 让两个名字指向同一个对象。可变对象一处改、处处可见；不可变对象因为无法原地改，才「看起来互不影响」。

```python-run
# 可变对象：两个名字指向同一个 list
a = [1, 2]
b = a
b.append(3)
print("a:", a, "b:", b)   # 两个都变了！

# 不可变对象：重绑不会影响对方
x = 10
y = x
y = 20
print("x:", x, "y:", y)   # x 还是 10
```

想真正复制一份可变对象，用 `list()`、`copy`、或 `copy.deepcopy`（见「深拷贝 vs 浅拷贝」）。

# 5. 可变对象作函数默认参数的坑

默认参数在**函数定义时**只求值一次，之后反复复用同一个可变对象，导致状态被「记住」：

```python-run
def add(item, buf=[]):     # ❌ buf 默认是同一个 list
    buf.append(item)
    return buf

print(add(1))              # [1]
print(add(2))              # [1, 2]，竟然记住了上次的结果！
```

正确写法：默认值用 `None`，在函数体内再创建：

```python-run
def add(item, buf=None):
    if buf is None:
        buf = []
    buf.append(item)
    return buf

print(add(1))              # [1]
print(add(2))              # [2]
```

# 6. 可变性与哈希

只有不可变对象才能被哈希，因此才能作 `set` 的元素或 `dict` 的 key。这是「可哈希性」的根源。

```python-run
hashable = {1, "a", (1, 2)}       # ✅ 都是不可变
print("可哈希集合:", hashable)

try:
    {[1, 2]}                      # ❌ list 可变，不可哈希
except TypeError as e:
    print("list 不可哈希:", e)
```

# 7. 嵌套的可变对象

不可变对象里若「装」了可变对象，外层不可变、内层照样能改：

```python-run
t = ([1, 2], 3)
t[0].append(99)         # tuple 本身不能改元素，但内部的 list 可以
print("嵌套可变对象:", t)

d = {"k": [1]}
d["k"].append(2)        # dict 的 key 不可变，value 是可变 list
print("dict 的可变 value:", d)
```

# 8. 小结

| 行为 | 不可变对象 | 可变对象 |
| --- | --- | --- |
| 修改方式 | 只能造新对象、重新绑定 | 原地改，id 不变 |
| 赋值 `a = b` | 重绑互不影响 | 共享引用，一处改处处变 |
| 可哈希 | ✅ | ❌ |
| 作默认参数 | 安全 | 有坑，用 `None` 兜底 |
| 典型 | int / str / tuple | list / set / dict |
