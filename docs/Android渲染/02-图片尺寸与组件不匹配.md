# 图片尺寸与组件不匹配

> **本质**:不匹配分两层——**解码层**:图比显示需要的大 → 白占内存,极端时 OOM;**布局层**:图和 View 形状不一致 → 变形/裁剪/留白,由 ScaleType 决定。**省内存靠解码,控观感靠 ScaleType。**

## 先分清三个"尺寸"

- **Bitmap 尺寸**(px):解码出来的真实像素大小,决定内存。`bitmap.width/height`。
- **View 尺寸**(px):measure/layout 之后才确定,决定显示区域。
- **intrinsic 尺寸**:图片自报的原始大小,`wrap_content` 的 View 拿它当参考。

不匹配就是这两件事:**Bitmap 比 View 需要的大**(内存问题)、**Bitmap 形状和 View 不一样**(视觉问题)。

## 解码层:图比显示需要的大,怎么办(管内存)

### 坑一:不指定尺寸,按原图解码

一张 4000×3000 的照片显示在 50dp 的 ImageView 里,内存照样按 45MB 算——OOM 发生在解码,和 View 多小无关。

**解法:按显示尺寸解码**

```kotlin
// Glide:自动等 View 量完尺寸,按它解码
Glide.with(iv).load(url).into(iv)
// View 尺寸未定时(如列表),显式给尺寸
Glide.with(iv).load(url).override(300, 300).centerCrop().into(iv)
```

手动解码的等价物:`inJustDecodeBounds` 先探尺寸 → `inSampleSize`(2 的幂)缩小再解码。

### 坑二:放错 density 目录,自动放大

`decodeResource` 默认按 **屏幕 dpi ÷ 资源目录 dpi** 缩放:100×100 的图放 `drawable-mdpi`,在 xxhdpi 设备上解码成 300×300,**内存 ×9**。资源按 density 目录成套放,或用 `drawable-nodpi` 表示"不要缩放"。

### 坑三:View 还没量尺寸就加载

Glide 的处理是等 measure 完成后再解码;自己手动解码时拿不到 View 尺寸,常退化成按整屏解码。列表场景显式 `override` 最稳。

## 布局层:形状不一致,怎么办(管视觉)

ScaleType 回答一个问题:**Bitmap 和 View 尺寸/形状不等时,绘制时怎么变换**(只改绘制矩阵,不省内存)。

| ScaleType | 保持宽高比 | 图片 < View | 图片 > View | 一句话记忆 |
| --- | --- | --- | --- | --- |
| `FIT_XY` | 否 | 拉伸铺满 | 压缩铺满 | 铺满就行,允许变形 |
| `FIT_CENTER`(默认) | 是 | **放大**贴合,可能留白 | 缩小完整显示 | 完整显示 + 居中 |
| `FIT_START` / `FIT_END` | 是 | 同上,贴顶/贴底 | 同上 | 对齐方向不同 |
| `CENTER` | — | 原样居中,不放大 | 原样,超出裁剪 | 我不缩放 |
| `CENTER_CROP` | 是 | 放大到铺满,居中裁剪 | 等比铺满,裁剪溢出 | 铺满优先,牺牲完整 |
| `CENTER_INSIDE` | 是 | **原样**,不放大 | 缩小完整显示 | 只缩不放 |
| `MATRIX` | 自定义 | 自定义 | 自定义 | 手势缩放/旋转 |

**高频混淆**:图片小于 View 时,`FIT_CENTER` 会放大(低分辨率小图标被拉糊),`CENTER_INSIDE` 保持原样。

**典型选择**:

- 头像、封面(宁可裁剪不能露底):`CENTER_CROP` + 固定尺寸。
- 截图、图表、整图预览(必须看全):`FIT_CENTER`。
- 手势缩放:`MATRIX`。

**背景没有 ScaleType**:`setBackground()` 直接把图拉伸铺满 View(等效 FIT_XY),非九宫格图当背景必变形。要圆角/边距就换 ImageView、`.9.png` 或 `layer-list`。

## 不匹配的实际后果速查

| 情况 | 后果 | 治法 |
| --- | --- | --- |
| 大图小视图 | 内存浪费、OOM | 解码时下采样 / override |
| 小图大视图 | 放大模糊 | 换高清资源,别指望 ScaleType |
| 形状不同 | 变形或裁剪或留白 | 选对 ScaleType |
| 长图巨图 | 一次解码太大 | `BitmapRegionDecoder` 分块显示 |

## 实践守则

- 一律按**目标 View 尺寸**解码:`into(view)` 自动;尺寸未定 `override`。
- 资源成套放 density 目录,别让自动密度缩放放大 9 倍。
- 背景用九宫格/inset,别指望 ScaleType。
- 头像封面 `CENTER_CROP` + 固定尺寸;小图标警惕被 FIT_CENTER 拉糊。
