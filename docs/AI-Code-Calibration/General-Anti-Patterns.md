# AI 代码通用防坑层（General Anti-Patterns）

> "AI 的错误不是随机发疯，而是人类历史开源代码中固有缺陷的映射与放大。"

---

## 一、过度设计 (Over-Engineering)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **不必要的抽象** | 一个 3 行函数需求，AI 生成 Factory + Interface + 实现类 | 问自己：这个抽象解决的是今天的问题还是明天的问题？明天的明天再说 |
| **过度参数化** | 把明确的功能写成接收 5 个参数的通用函数 | 先写死逻辑，等第二个调用者出现时再抽象 |
| **为未来写代码** | `/* TODO: 未来可能支持 X */` 为核心逻辑加分支 | 删掉，YAGNI（You Ain't Gonna Need It） |
| **Wrapper Hell** | 包装标准库/框架原生功能一层又一层却不提供额外价值 | 直接调用底层 API，除非包装层确实有行为变化 |

---

## 二、莫须有的 API (Hallucination)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **捏造方法名** | `file.read_text_with_encoding()`、`array.removeLast()` | 任何不认识的 API 先查文档 |
| **拼凑参数** | 用对了类名但参数名/顺序凭空编造 | IDE 补全是第一道防线 |
| **混搭不同版本的 API** | v1 的类名 + v2 的参数格式 | 锁死版本号后让 AI 也明确版本上下文 |
| **假导入路径** | `from lib.util.magic import solve` —— 这个文件根本不存在 | 编译通过后再往下走 |

## 三、错误处理反模式 (Error Handling)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **空 catch / 吞异常** | `try { ... } catch { }` 或 `except: pass` | 至少要 log，或明确标注为什么可以吞 |
| **万能捕获** | `except Exception as e: print("出错了")` | 只捕获你预期会发生的异常类型 |
| **异常驱动流程控制** | 用 `try` 检测 key 是否存在而不是 `if key in dict` | 异常是给"异常情况"用的，不是控制流 |
| **错误返回值不一致** | 异常抛一半，另一半 return None/-1 | 选一种风格坚持到底 |
| **重试无上限** | 无限重试而不带退避策略 | 必须有最大重试次数 + 指数退避 |

## 四、隐式假设 (Implicit Assumptions)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **假设输入非空** | `list[0]` 没有长度检查 | 边界先判 |
| **假设数据格式** | 把字符串当 JSON 解析而不确认格式 | 解析前校验 |
| **假设环境变量存在** | `os.environ["SECRET"]` 直接取不设默认值 | 用 `.get()` 或集中校验 |
| **假设字符串是 UTF-8** | 不指定编码就 `open(file)` | 显式指定 `encoding="utf-8"` |
| **假设时区** | 默认 UTC 但不声明，或用了本地时区却按 UTC 比较 | 永远显式处理时区 |
| **假设幂等性** | 同一个函数调两次结果一样 —— AI 认为理所当然，实际未必 | 区分读操作（应幂等）和写操作（可能不幂等） |

## 五、状态一致性问题 (State Consistency)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **部分更新** | 更新了对象 A 但关联对象 B 没同步 | 事务/原子性，或至少原子性注释 |
| **缓存过期** | 改了原始数据，缓存层没失效 | 单点写入 + 写入时失效缓存 |
| **条件反转** | `if flag:` → 实际应该是 `if not flag:` | 给布尔变量起 `is_xxx`/`has_xxx` 名，降低反转概率 |
| **离线不一致** | 前端改了本地状态但没提交到后端 | 明确 single source of truth |

## 六、安全基础红线 (Security)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **硬编码密钥** | `API_KEY = "sk-xxx"` 写死 | 环境变量 / Secret Manager |
| **SQL 拼接** | `f"SELECT * FROM users WHERE id={user_input}"` | 参数化查询 |
| **命令注入** | `os.system(f"ping {user_host}")` | 子进程用数组参数而非字符串拼接 |
| **路径遍历** | `open(user_filename)` 不加校验 | 校验文件名不含 `../`、限制在 base_dir 内 |
| **日志泄露** | `log.info(f"用户信息: {user}")` 打印密码/token | 日志脱敏 |
| **缺少限流** | API 接口不限调用频率 | 必须有 rate limit |

---

## 七、性能陷阱 (Performance)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **N+1 查询** | 循环里逐条查数据库/发 HTTP 请求 | 批量查询 |
| **循环内构造大对象** | `for i in range(n): result.append(large_func())` 无谓分配 | 复用/懒加载 |
| **不设超时** | HTTP client 默认无限等待 | 所有网络调用设 timeout |
| **忘记关闭资源** | 文件、连接、socket 不 close | with/use/try-with-resources |
| **print 用于生产** | `print("===== debug =====")` 留在正式代码 | 用 logger |
| **同步阻塞** | I/O 密集操作写在主线程里阻塞 UI/Event Loop | 异步化或丢到 worker |

---

## 八、空值/边界处理 (Null & Boundaries)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **不判空** | `user.name.upper()` 直接调用可能为 None 的属性 | 链式调用中间环节加判空 |
| **falsy 误判** | `if value:` 把 `0`、`""`、`[]` 当成无效 | 用 `if value is None` 精确判空 |
| **索引越界** | `items[len(items)]` | 看一眼索引范围 |
| **除零** | `avg = total / len(items)` 没检查 `len(items) == 0` | 先判除数 |
| **负数/零作为除数** | `for i in range(items - 1)` 当 items=0 时 `range(-1)` 不报错但逻辑错 | 显式检查边界 |

---

## 九、拷贝粘贴后遗症 (Copy-Paste Drift)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **变量名没改干净** | 复制了一段代码逻辑但其中某处变量还是原名 | 复制后逐行 diff |
| **注释和代码脱节** | 改了代码但上面注释说相反的逻辑 | 删掉注释比留着错误注释好 |
| **处处相似但处处不同** | 同一个逻辑在 3 个地方各自"微调" | 抽成一个函数，参数化差异 |
| **死代码** | if-else 中 if 已经 return 了，else 后面的代码永远不会执行 | lint/IDE 灰掉后删 |

## 十、错误的依赖与配置 (Dependency & Config)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **隐式全局依赖** | 函数内部直接 import 导致不可测 | 依赖注入或至少参数化 |
| **配置散落各处** | 端口号、阈值写死在各个文件不同位置 | 集中配置中心 |
| **不兼容的依赖版本** | `requirements.txt` 不 pin 版本 | 锁文件 + 版本范围 |
| **循环依赖** | A import B，B import A | 架构上不该出现 |

---

## 十一、并发与异步陷阱 (Concurrency)

| 模式 | 表现 | 纠正 |
|------|------|------|
| **竞态条件** | 两个协程同时读写一个变量 | 锁/原子操作/不可变数据结构 |
| **死锁** | A 等 B 释放锁，B 等 A 释放锁 | 统一加锁顺序；超时释放 |
| **忘记了 await** | `async def foo(): bar()` 没 await，返回 coroutine 对象 | lint 规则强制 |
| **混合同步和异步** | 在 async 函数里调用 `time.sleep()` | 用 `asyncio.sleep()` |

## 检查清单

每当 AI 生成的代码进入 Review 流程，对照以下问题快速扫描：

- [ ] 这个 API 方法真的存在吗？（编译/运行第一步验证）
- [ ] 有 hardcode 的密钥、URL、端口号吗？
- [ ] 有吞掉的异常吗？（`except:` / `catch {}`）
- [ ] 输入为空/负数/边界值时会怎样？
- [ ] 文件/连接有没有 close？
- [ ] 是不是为了 3 行逻辑建了 5 个类？
- [ ] 布尔条件有没有反转？
- [ ] 两段几乎一样的代码能不能抽成一个？
