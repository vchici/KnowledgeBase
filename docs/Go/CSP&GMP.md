# CSP 并发模型

> 核心哲学（Go 官方）：**不要用共享内存来通信，用通信来共享内存。**

- goroutine 之间通过 channel 传递数据，替代「加锁 + 共享变量」的协作方式
- 发送语义：向 channel 发送是**值拷贝**
  - 传值类型（int、struct…）：安全，天然隔离
  - 传引用类型（指针、slice、map…）：底层仍是共享数据，**同样有竞态风险**
  - 结论：channel 本身并发安全，但「用了 channel 就不会有竞态」是误解

## 阻塞规则

| channel 类型 | 发送 | 接收 |
|-------------|------|------|
| 无缓冲 | 阻塞，直到有接收方就绪 | 阻塞，直到有发送方就绪 |
| 有缓冲（容量 N） | 缓冲满才阻塞 | 缓冲空才阻塞 |

> 无缓冲 channel 是同步的（发送=交接）；有缓冲 channel 是异步的（解耦生产/消费）。

# GMP 调度模型

## 三个角色

```
        G   G   G   G   G          G = goroutine，用户态协程任务
        |   |   |   |   |            栈初始 2KB，动态增长，轻量
        ┌───────────┐
        │ P   P   P │              P = processor，调度上下文，
        └───────────┘                持有本地可运行 G 队列（runqueue）
        |   |   |
        M   M   M                   M = machine，操作系统线程（OS thread）
        |   |   |
      CPU CPU CPU                   CPU 是硬件，M 在 CPU 上真正执行
```

- **G（goroutine）**：用户态任务上下文，栈小、切换在用户态完成，一个进程可承载数十万 G
- **M（machine）**：操作系统线程，真正执行代码的载体
- **P（processor）**：调度器上下文，持有本地 G 队列；M 必须先绑定一个 P 才能执行 G

## 数量关系

| 角色 | 数量 |
|------|------|
| P | = GOMAXPROCS（默认 = CPU 核数） |
| M | ≥ P；系统调用阻塞时可临时新建 M |
| G | 无上限（成千上万） |

## 调度流程

1. 新建 G → 放入某个 P 的本地队列（本地满则进全局队列）
2. M 从所绑定 P 的本地队列取出 G 执行
3. 本地队列空了 → **work stealing**（偷其他 P 的 G）或取全局队列
4. Go 1.14+：**抢占式调度**（基于信号），防止单个 G 长期霸占 M 让其他 G 饥饿

## 阻塞场景（重点）

### 场景一：系统调用阻塞（文件 IO、Syscall）

```
G1 发起阻塞系统调用
  → G1 和 M1 一起进入内核态等待（M1 阻塞在 syscall，不是"sleep"）
  → P 与 M1 解绑（hand off），P 绑定空闲的 M2 继续执行其他 G
  → 系统调用返回后，G1 重新放入某个 P 的队列，等待调度
```

### 场景二：用户态阻塞（网络 IO，netpoller）

```
G1 发起网络请求
  → 基于 epoll/kqueue 的非阻塞 IO，G1 与 M1 解绑，G1 进入等待队列
  → M1 不被阻塞，立即继续执行其他 G（这就是网络高并发的关键）
  → 网络事件就绪，G1 被唤醒，放入某个 P 的队列，由任意空闲 M 执行
```

> 关键点：**G 与 M 没有固定绑定关系**。G 被唤醒后不保证回到原来的 M。

## 为什么 goroutine 比线程轻量

| | 线程（如 Java） | goroutine |
|---|---|---|
| 栈大小 | ~1MB（固定） | 2KB 起步（动态伸缩） |
| 调度 | 1:1 内核线程，切换涉及内核态 | M:N 调度，切换在用户态 |
| 创建成本 | 高（内核资源） | 极低 |

# 补充：channel 底层（hchan）

- channel 内部是 `hchan` 结构：包含互斥锁、发送队列、接收队列、环形缓冲区
- 发送/接收在队列中等待的 goroutine 会进入睡眠（G 状态变为 waiting）
- channel 的并发安全就来自这把内部锁

# 一句话总结

> GMP 的终极目标：**用少量 OS 线程（M）跑海量 goroutine（G）**，网络 IO 不阻塞线程、系统调用用换 P 的方式兜底，从而支撑极高并发。
