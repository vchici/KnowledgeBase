# 项目包装：本地数据库设计（要点速记）

> 总准则：**一张表只装一个实体（一种事物），字段只描述这个实体自己的属性。**

## 一、拆表准则（什么时候拆）

表 = 实体类型，行 = 该类型的一个实例，列 = 段实体的属性

## 二、索引

读多写少，区分度高的列，建索引。
联合索引，区分度高的放前面，遵循最左前缀，范围条件后面的列索引会失效
选用自增主键，不要用随机值主键

## 三、事务（什么时候用）

事务保证的是单个数据库中的操作的原子性
Spring @Transactional 注解 通过 AOP，
```asciidoc
调用方
  │
  ▼
【代理对象】← Spring AOP 生成的
  │ ① 拿到数据库连接，setAutoCommit(false)（事务开始）
  │ ② 调用你真正的业务方法
  │ ③ 方法正常返回 → commit()
  │    方法抛异常并传出 → rollback()
  ▼
你的业务方法
```
使用 @Transactional 要注意
1. 如果使用方法的对象不归Spring管理，事务不会生效。
2. 如果方法中try catch了异常，AOP的拦截器拦不到异常，事务不会回滚，需要手动标记。
3. 不要把事务写在private内部方法，AOP会失效。

## 四、WAL（什么时候开）

- **一边写库、一边读库**时需要（分析线程在写结果、UI 线程在读报告）
- 默认模式读写互斥会卡；WAL 让读写不互斥

## 五、数据分块存储（本项目真实架构）

- **结构**：一次体检 = 一个独立数据块（独立 SQLite 文件 / 数据目录），每次体检有独立查看入口，**点击现查**
- **好处**：
  - 数据天然隔离：删/改一次体检只动它自己的块
  - 按需加载：不点开不加载，天然不背全量数据
  - 自带冷热分离：旧体检就是旧块，不参与日常查询，清理 = 删块
- **注意**（真正要讲的两个点）：
  - 需要一张**体检索引表**（轻量）：记录 体检ID、时间、状态、块路径，否则列表页要扫所有块
  - 块内查询同样靠索引/过滤
- 与「冷热归档」的关系：冷热归档针对"一张表无限累加"；**分块架构自带冷热分离，不需要归档机制**
