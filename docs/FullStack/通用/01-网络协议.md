# 网络协议

> 前后端一切数据交互的基石。无论前端调接口还是后端写服务，都是围绕 HTTP 展开。

## TCP 基础

### 三次握手

建立连接：`SYN → SYN+ACK → ACK`

- 为什么三次而不是两次：双方都要确认「自己发送、对方接收」能力，防止过期连接请求到达
- 第 3 次可以携带数据

### 四次挥手

断开连接：`FIN → ACK → FIN → ACK`

- 为什么四次：TCP 全双工，每一方向都需要独立关闭
- TIME_WAIT 状态：等待 2MSL，确保最后的 ACK 到达、旧连接报文消亡

## HTTP 协议

### HTTP 特点与请求流程

1. 无状态：每次请求独立 → 需要 Cookie/Session/Token 维持状态
2. 请求报文：请求行（方法+URL+版本）、请求头、请求体
3. 常见方法语义：GET（幂等读）、POST（创建）、PUT（整体更新）、PATCH（部分更新）、DELETE

### 常见状态码

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 301 / 302 | 永久 / 临时重定向 |
| 304 | 未修改（协商缓存命中） |
| 400 / 401 / 403 / 404 | 参数错误 / 未认证 / 无权限 / 不存在 |
| 429 | 请求过多（限流） |
| 500 / 502 / 503 | 服务器错误 / 网关错误 / 服务不可用 |

### HTTP 版本演进

| 版本 | 关键特性 |
|------|---------|
| HTTP/1.1 | 持久连接、管道化（实际用得少）、队头阻塞 |
| HTTP/2 | 多路复用（一个连接并发请求）、头部压缩 HPACK、服务端推送 |
| HTTP/3 | 基于 QUIC（UDP），解决 TCP 队头阻塞，减少握手 RTT |

## HTTPS

- 加密过程：**非对称加密协商会话密钥 + 对称加密传输数据 + 证书防篡改**
- 握手流程：ClientHello → ServerHello+证书 → 客户端验证证书（CA 链）→ 生成预主密钥（RSA/ECDHE）→ 双方计算会话密钥 → 之后对称加密通信
- 为什么用混合加密：非对称慢但安全（密钥交换），对称快（数据传输）

## WebSocket

- 全双工长连接，服务端可主动推送（聊天、实时通知、协同编辑）
- 与 HTTP 关系：通过 `Upgrade` 握手升级协议
- vs SSE：WebSocket 双向，SSE 单向服务端推送（简单、自动重连）

## 前端必懂的网络知识

- CORS 跨域：同源策略、预检请求（OPTIONS）、Access-Control-Allow-Origin
- 浏览器缓存策略：强缓存（Cache-Control/Expires）vs 协商缓存（ETag/Last-Modified）
- CDN：静态资源就近分发
