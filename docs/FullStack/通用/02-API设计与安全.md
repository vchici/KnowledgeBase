# API 设计与安全

> API 是前后端的「合同」。设计得好，前后端协作顺畅；安全做得差，整个系统不堪一击。

## API 设计规范

### 接口契约

- 接口文档先行：OpenAPI（Swagger）自动生成文档
- 统一响应结构：`{ code, message, data }`，前端只认 `code`
- 字段命名统一：camelCase（前端）vs snake_case（后端），由 BFF 层转换
- 分页规范：`page` / `pageSize` / 返回 `total`

### 错误处理

```json
// 业务错误与系统错误区分
{
  "code": 10001,
  "message": "用户不存在",
  "data": null
}
```

- 错误码分段规划：1xxxx 用户、2xxxx 订单、3xxxx 支付…
- 永远不要把系统异常堆栈直接返回给前端
- 前后端错误提示策略：code 映射到用户可读文案

### 版本管理

- 破坏性变更必须升版本：`/api/v1/users` → `/api/v2/users`
- 兼容策略：旧版本保留一段时间、灰度迁移、双写过渡

## 安全体系

### 前端注入攻击

| 攻击 | 场景 | 防御 |
|------|------|------|
| XSS（跨站脚本） | 评论、富文本注入恶意脚本 | 输出转义、CSP、HttpOnly Cookie |
| CSRF（跨站请求伪造） | 用户已登录，恶意网站冒用身份发请求 | 同源校验、CSRF Token、SameSite Cookie |
| 点击劫持 | iframe 套嵌诱导点击 | X-Frame-Options |

### 后端注入攻击

| 攻击 | 防御 |
|------|------|
| SQL 注入 | 参数化查询（PreparedStatement）、ORM 默认转义 |
| 命令注入 | 禁止拼接系统命令、白名单校验 |
| 路径穿越 | 校验上传文件名、限制访问目录 |

### 认证授权相关

- 越权（IDOR）：水平越权（改 id 看别人数据）→ 校验资源归属；垂直越权（普通用户调管理接口）→ RBAC 权限校验
- 登录安全：密码哈希存储（bcrypt，绝不存明文）、验证码防暴力破解、登录限流
- Token 安全：短期 access token + refresh token、黑名单主动失效、敏感操作二次验证

### 传输与存储安全

- 全站 HTTPS，禁止明文传输敏感字段
- 敏感字段脱敏：手机号、身份证打码展示
- 前端不存储敏感信息：勿把密钥/token 放 localStorage（XSS 可读）→ HttpOnly Cookie

## 常见面试题

1. XSS 与 CSRF 的区别？如何防御？
2. 接口如何防止被刷（限流 + 验证码）？
3. 如何防止水平越权？
4. 密码在数据库中如何安全存储？
5. 前后端如何统一处理错误与提示？
