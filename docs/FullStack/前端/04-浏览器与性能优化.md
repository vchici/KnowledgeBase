# 浏览器与性能优化

## 从输入 URL 到页面渲染

完整链路（高频面试题）：

1. **DNS 解析**：域名 → IP（本地缓存 → 递归查询）
2. **TCP 连接**：三次握手（HTTP/2 可多路复用）
3. **发送 HTTP 请求**：请求行、请求头、请求体
4. **服务器响应**：状态码、响应头、响应体
5. **浏览器解析**：
   - 解析 HTML 构建 DOM 树
   - 解析 CSS 构建 CSSOM 树
   - 合并成渲染树（Render Tree）
6. **布局（Layout/Reflow）**：计算元素几何位置
7. **绘制（Paint）**：绘制像素，合成（Composite）到屏幕

## 渲染原理关键点

- **重排（Reflow）**：改几何属性（宽高、位置）→ 代价最大
- **重绘（Repaint）**：改外观（颜色、背景）→ 不涉及布局
- **合成（Composite）**：只影响图层（transform/opacity）→ 性能最好，交给 GPU
- **优化手段**：批量操作 DOM、`requestAnimationFrame`、`will-change`、避免强制同步布局

```javascript
// 避免：读取 + 写入交替，触发强制同步布局
element.style.width = '100px'
console.log(element.offsetWidth)  // 强制 reflow！
element.style.height = '200px'

// 建议：读操作集中，写操作集中
const w = element.offsetWidth  // 先读
element.style.width = '100px'  // 再写
element.style.height = '200px'
```

## 性能优化全景

### 加载阶段

| 手段 | 原理 |
|------|------|
| 打包体积优化 | 代码分割、按需引入（如 lodash 按需）、压缩 |
| 静态资源 CDN | 就近分发，减少 RTT |
| 浏览器缓存 | 强缓存（Cache-Control）+ 协商缓存（ETag/Last-Modified） |
| 图片优化 | WebP/AVIF、懒加载、响应式尺寸 |
| 字体优化 | 字体子集化、`font-display: swap` |
| 预加载 | `<link rel="preload">` 关键资源 |

### 渲染阶段

- 减少 DOM 层级和数量
- 避免重排重绘（样式集中、transform 替代 top/left）
- 虚拟列表：长列表只渲染可视区域
- 组件懒加载 + 路由懒加载

### 运行时

- 防抖（debounce）/ 节流（throttle）：滚动、搜索、resize
- Web Worker：大数据量计算不阻塞主线程
- 内存泄漏排查：全局变量、定时器未清理、事件监听未移除、闭包持有大对象
- 长任务拆分：`requestIdleCallback` 处理低优先级任务

## 性能指标

| 指标 | 含义 | 优化目标 |
|------|------|---------|
| FCP | 首次内容绘制 | 减少阻塞渲染的 CSS/JS |
| LCP | 最大内容绘制 | 首屏主体快速呈现 |
| CLS | 布局偏移 | 稳定页面布局，预留空间 |
| TTI | 可交互时间 | 减小 JS 执行耗时 |
| TBT | 阻塞总时间 | 拆分长任务 |

> 工具：Chrome DevTools Performance / Lighthouse / Web Vitals
