# 前端框架与原理

## 选型现状

| 框架 | 特点 | 适用 |
|------|------|------|
| React | 生态最大、函数组件 + Hooks、虚拟 DOM | 大型中后台、跨端 RN、Next.js 服务端渲染 |
| Vue 3 | 上手平缓、Composition API、响应式 + 模板编译 | 国内企业级项目主力 |
| Svelte | 编译时框架、无虚拟 DOM | 轻量场景 |
| Solid | 细粒度响应式 | 前沿探索 |

> 建议：**精一门，通原理**。框架会迭代，但「虚拟 DOM / 响应式 / 组件化」的底层思想不变。

## 必须吃透的原理

### 1. 虚拟 DOM（React）

- 为什么需要：直接操作 DOM 代价高，虚拟 DOM 用 JS 对象描述 UI，diff 后批量更新
- Diff 算法核心：同层比较、key 复用、O(n) 复杂度
- 为什么 key 不能滥用 index：列表顺序变化会导致复用错误

### 2. 响应式系统（Vue 3）

> **本质：发布-订阅。** 读数据时记下「谁在用」（依赖收集），改数据时通知「用的人」重新执行（触发更新）。Proxy 的 get / set 拦截是两个入口。

| 角色 | 职责 |
|------|------|
| `effect` | 全局指针，指向「正在运行的函数」（如渲染函数），用来标记是谁在读数据 |
| `deps` | 订阅表：`属性名 → 依赖它的所有函数`（Set） |
| `reactive` | 用 Proxy 包一层对象，拦截读（get）和写（set） |

```javascript
// Vue 3 基于 Proxy 的响应式核心思路（最小实现）
let effect = null          // 正在运行的函数；为 null 表示当前不在收集时机
const deps = new Map()     // 订阅表：key → Set<依赖它的函数>

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) {
      if (effect) {
        // ① 依赖收集：有函数在读该属性 → 记入它的订阅名单
        if (!deps.has(key)) deps.set(key, new Set())
        deps.get(key).add(effect)
      }
      return target[key]
    },
    set(target, key, value) {
      target[key] = value
      // ② 触发更新：该属性变了 → 重跑订阅它的所有函数
      deps.get(key)?.forEach(fn => fn())
      return true
    }
  })
}
```

```javascript
// 使用效果
const state = reactive({ count: 0 })

effect = () => console.log('count =', state.count)
effect()          // count = 0：执行时读了 state.count，函数被记入 count 的名单

state.count = 1   // count = 1：修改触发 set 拦截，自动重跑，无需手动调用
```

**Vue 2 `Object.defineProperty` vs Vue 3 `Proxy`**

| | defineProperty（Vue 2） | Proxy（Vue 3） |
|---|---|---|
| 劫持粒度 | 已存在的**单个属性** | **整个对象**的所有操作 |
| 新增 / 删除属性 | 监听不到，需 `$set` / `$delete` 补救 | 天然支持 |
| 数组索引赋值、`length` | 监听不到，需重写数组方法 | 天然支持 |

> 这是简化模型。真实 Vue 3：订阅表按 `WeakMap<对象, Map<属性, Set<函数>>>` 三层组织，支持多个响应式对象；effect 嵌套用栈管理；重新执行前先清除旧依赖，避免 `v-if` 等分支变化导致的多余更新。

> **可运行实验**：浏览器打开 [examples/vue3-reactivity.html](/examples/vue3-reactivity.html)，点按钮改数据，对照右侧 deps 订阅表和事件日志理解「收集 / 触发」。

### 3. Hooks 机制（React）

- useState / useEffect / useMemo / useCallback / useRef 的职责
- 为什么 Hooks 不能写在条件语句里（调用顺序依赖）
- useEffect 的依赖数组与闭包陷阱
- 自定义 Hook：抽离可复用逻辑

### 4. 组件通信

| 方式 | 适用场景 |
|------|---------|
| props 单向数据流 | 父子组件 |
| 事件回调 / 自定义事件 | 子传父 |
| 插槽 slot | 布局模板复用 |
| provide/inject（Vue）/ Context（React） | 跨层级 |
| 状态管理库 | 全局共享：Pinia（Vue）/ Redux、Zustand（React） |

### 5. 状态管理

- 为什么需要：多个组件共享状态、跨页面状态
- 核心原则：单一数据源、状态不可变更新、单向数据流
- Pinia vs Redux：Pinia 更轻（去掉 reducer 样板），Redux 生态更全（中间件、DevTools）

## 路由与渲染模式

| 模式 | 说明 | 应用 |
|------|------|------|
| SPA | 前端路由，首屏 JS 渲染 | 大部分中后台 |
| SSR | 服务端渲染 HTML | SEO、首屏性能（Next.js/Nuxt） |
| SSG | 构建时生成静态页 | 文档站、博客（本知识库即 VitePress） |

## 常见面试题

### 1. Vue 的响应式原理？Vue 2 与 Vue 3 的实现差异？

**原理：发布-订阅。** 读数据时依赖收集（记下谁在用），改数据时触发更新（通知用的人重新执行）。

| | Vue 2：`Object.defineProperty` | Vue 3：`Proxy` |
|---|---|---|
| 劫持粒度 | 逐个劫持**已存在属性**的 get/set | 代理**整个对象**的所有操作 |
| 新增 / 删除属性 | 监听不到，需 `$set` / `$delete` | 天然支持 |
| 数组索引赋值 / `length` | 监听不到，需重写数组方法 | 天然支持 |
| 性能 | 初始化需递归遍历所有属性 | 惰性代理，访问到才递归 |

> 细节与最小实现见上文「响应式系统」。

### 2. React 虚拟 DOM diff 算法如何工作？为什么 key 重要？

**虚拟 DOM**：用 JS 对象描述 UI。状态变化 → 生成新树 → 与旧树 diff → 算出最小变更 → 批量更新真实 DOM。

diff 的三个策略（将 O(n³) 降到 O(n)）：

1. **同层比较**：不跨层级移动节点，跨层视为「删除 + 重建」
2. **类型不同直接替换**：type 不同则销毁整个子树重建，不再深入比较
3. **key 标识子元素**：同级列表按 key 匹配复用

**key 为什么重要**：diff 靠 key 判断「这个节点是原来那个」，从而复用 DOM、保留组件内部状态。用 index 作 key 时，插入 / 删除 / 排序会让 key 错位 → 状态串位（如输入框内容错乱）、多余重渲染。key 要求**稳定且唯一**。

### 3. useEffect 与 useLayoutEffect 的区别？

核心区别是**执行时机**：

| | useLayoutEffect | useEffect |
|---|---|---|
| 时机 | DOM 更新后、**浏览器绘制前**同步执行 | **绘制完成后**异步执行 |
| 是否阻塞 | 阻塞渲染 | 不阻塞 |
| 场景 | 绘制前测量 / 修改 DOM 布局（避免闪烁） | 数据请求、订阅、事件监听等大多数副作用 |

> SSR 下 useLayoutEffect 无意义且会告警（服务端没有绘制阶段），默认用 useEffect。

### 4. 组件间通信的方式有哪些？如何选择？

方式见上文「组件通信」表格。选择思路：

1. 父子 → props 单向数据流 + 事件回调
2. 兄弟 → 状态提升到共同父级
3. 跨层级 → provide/inject（Vue）、Context（React）
4. 全局共享 → 状态管理库（Pinia / Redux / Zustand）
5. 避免滥用 EventBus：数据流不可追踪，仅极简单场景使用

### 5. 前端路由的实现方式（hash vs history）？

| | hash | history |
|---|---|---|
| 原理 | 改变 URL `#` 后的部分，监听 `hashchange` | `pushState` / `replaceState` 改 URL + `popstate` 监听前进后退 |
| 刷新 | 不发请求、不刷新 | 不刷新，但**手动刷新需服务端回退到 index.html**，否则 404 |
| URL | 带 `#`，不美观 | 正常路径，美观、利于 SEO |
| 兼容性 | 全兼容 | 需浏览器支持 History API |

vue-router / React Router 内部就是基于这两种模式封装。

### 6. SPA 首屏加载慢，如何优化？

**根源**：JS 包体积大 + 首屏要等 JS 下载执行完才渲染。

- **减小体积**：路由懒加载（动态 import 按需分包）、Tree Shaking、组件库按需引入、代码压缩
- **加速传输**：HTTP/2、Gzip / Brotli、CDN、强缓存 + 文件名 hash
- **提前渲染**：SSR / 预渲染让 HTML 直出；关键 CSS 内联，JS 加 defer / async
- **改善体验**：骨架屏、loading 过渡
- **先度量再优化**：用 Lighthouse / Performance 面板看 FCP、LCP 卡在哪一步
