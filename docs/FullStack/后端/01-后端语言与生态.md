# 后端语言与生态

> 这一篇回答「后端学什么语言、语言之外还要会什么」。
>
> 记忆主线：**选对工具（选型）→ 用好工具（语言核心）→ 跳出工具看不变能力（通用基本功）**。
>
> 底层信念：语言只是工具，真正值钱的是网络、数据库、并发、架构这些**不随语言变**的知识。

## 一、主流选型：按场景选工具，别迷信某门语言

| 语言 | 框架 | 特点 | 适合 |
|------|------|------|------|
| Java | Spring Boot | 生态最全、稳定、企业级 | 大型业务系统、银行/电商 |
| Go | Gin / Kratos | 高并发、单二进制易部署、性能好 | 中间件、微服务、云原生 |
| Node.js | Express / NestJS | 前后端同语言、I/O 密集 | BFF 层、快速原型 |
| Python | FastAPI / Django | AI 生态强、开发快 | AI 服务、数据平台 |
| Rust | Axum / Actix | 极致性能与安全 | 基础设施、高性能服务 |

> 建议：**精通一门（Java 或 Go），理解其他**。语言会过时，网络/数据库/并发/架构不会。

## 二、语言核心：学透一门语言的「内存 / 并发 / 框架」三件套

**本质**：任何语言都能拆成三块底层——**内存怎么管、并发怎么写、框架怎么搭**，学透一门即可迁移到其他语言。

### Java

- **内存**：JVM 内存模型（堆/栈/方法区）、GC 机制（分代回收、G1/ZGC）
- **并发**：synchronized / ReentrantLock / AQS / 线程池 / volatile / CAS
  - 关联笔记：[synchronized 详解](../../Thread/Lock/synchronized.md)
- **集合（含并发容器）**：ArrayList vs LinkedList、HashMap 原理（数组+链表+红黑树）、ConcurrentHashMap（分段锁/CAS）
- **框架**：Spring 生态——IoC/DI、AOP、Bean 生命周期、事务传播
  - 关联笔记：[Spring通关-2-IoC-DI](../../JavaWeb/Spring通关-2-IoC-DI.md)、[Spring通关-4-AOP与数据库](../../JavaWeb/Spring通关-4-AOP与数据库.md)
- **工程化**：异常体系与日志（SLF4J + Logback）

### Go

- **并发**：goroutine 与 channel——GMP 调度模型、CSP 并发模型
  - 关联笔记：[Goroutine](../../JavaWeb/Goroutine.md)
- **语言特性**：指针与值传递、接口（鸭子类型）、错误处理（error 值 vs panic）
- **标准库**：net/http、context、sync 包
- **微服务框架**：Kratos / Go-zero，rpc（gRPC）

## 三、通用能力：换任何语言都逃不掉的后端基本功

**本质**：语言是表层，下面这些是后端通用的「骨架」，语言换了它们还在。

1. **HTTP 服务编程**：路由、中间件、请求上下文、状态码语义
2. **Web 框架原理**：Servlet/Filter/拦截器、AOP 适用场景
3. **多线程与异步**：线程池参数设计、异步任务、消息驱动
4. **数据访问**：ORM 用法与原生 SQL 的平衡、事务管理
5. **参数校验与错误处理**：统一响应结构、全局异常、校验注解/中间件
6. **测试**：JUnit/Go test、Mock、Testcontainers

## 常见面试题

> 点击展开参考答案，先自测再看。

### 1. HashMap 底层原理？ConcurrentHashMap 如何保证线程安全？

<details><summary>参考答案</summary>

**HashMap**：数组 + 链表 + 红黑树。key 哈希定位桶，冲突挂链表，链表超 8 且数组超 64 转红黑树。扩容（负载因子 0.75）时重哈希，JDK 8 用高低位拆分减少迁移。

**ConcurrentHashMap**：JDK 8 用 **CAS + synchronized 锁单个桶**（不再用分段锁）。读操作无锁（volatile 保证可见性），写只锁冲突的那一桶，并发度从「段数」提升到「桶数」。

</details>

### 2. 线程池核心参数如何设置？

<details><summary>参考答案</summary>

核心参数：核心线程数、最大线程数、队列、拒绝策略、存活时间。

- 线程数经验值：CPU 密集 `N+1`；IO 密集 `2N` 或按 `N * (1 + 等待时间/计算时间)`（N 为核数）
- 队列：用有界队列（ArrayBlockingQueue）防 OOM，无界队列在突发流量下会无限堆积
- 拒绝策略：默认 AbortPolicy 抛异常；CallerRunsPolicy 让提交线程自己跑，天然背压

</details>

### 3. Spring Bean 的生命周期？

<details><summary>参考答案</summary>

实例化 → 属性注入 → `BeanNameAware`/`BeanFactoryAware` 回调 → `BeanPostProcessor` 前置处理 → `@PostConstruct` → `InitializingBean` → `BeanPostProcessor` 后置处理（**AOP 代理在此生成**）→ 使用 → `@PreDestroy` 销毁。

面试重点：AOP 代理在后置阶段生成，所以同类自调用 `this.method()` 绕过了代理，事务/切面不生效。

</details>

### 4. Spring 事务什么时候会失效？

<details><summary>参考答案</summary>

- **自调用**：同类内 `this.method()` 绕过代理，事务注解不生效
- **异常被吞**：try-catch 吃掉异常，事务感知不到，不回滚
- **非受检异常**：默认只回滚 RuntimeException/Error，受检异常需 `rollbackFor` 指定
- **方法非 public**：代理无法拦截
- **传播属性错误**：如 `NOT_SUPPORTED` 挂起事务
- 数据库引擎不支持事务（MyISAM）

</details>

### 5. goroutine 与线程的区别？GMP 调度模型？

<details><summary>参考答案</summary>

| 维度 | goroutine | 线程 |
|------|----------|------|
| 栈大小 | 初始 2KB，可动态伸缩 | 默认 1MB，固定 |
| 切换 | 用户态，成本低 | 内核态，成本高 |
| 数量 | 可轻松百万级 | 受内存和调度限制 |

**GMP**：G（goroutine）、M（内核线程）、P（逻辑处理器，持有本地 runq）。P 数量 = `GOMAXPROCS`；M 从 P 的本地队列取 G 执行，本地空则 work-stealing 偷别的 P 的 G。G 阻塞时 M 让出，P 找新 M 继续跑——实现「用户态调度 + 复用内核线程」。

</details>

### 6. JVM 内存泄漏如何排查？

<details><summary>参考答案</summary>

- 现象：老年代持续增长、Full GC 后内存仍不降、最终 OOM
- 工具：`jps` 找 pid → `jmap -dump` 导出堆 → MAT/VisualVM 分析；`jstat -gcutil` 看各代占用趋势
- 定位：从 GC Roots 找对象引用链，看谁被长期持有（静态集合、ThreadLocal 未 remove、未关闭的流/连接）
- 关联笔记：[内存泄漏](../../GC/内存泄漏.md)

</details>
