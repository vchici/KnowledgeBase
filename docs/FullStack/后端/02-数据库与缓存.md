# 数据库与缓存

## 关系型数据库（MySQL）

### 索引原理

- 为什么索引快：B+ 树结构，IO 次数 = 树高（3~4 层），叶子节点有序链表利于范围查询
- 聚簇索引 vs 非聚簇索引（InnoDB 主键索引存整行，二级索引存主键 → 回表）
- 联合索引的最左前缀原则、覆盖索引避免回表

**索引失效场景**（高频面试）：

- 对索引列使用函数或计算：`WHERE YEAR(create_time) = 2024`
- 隐式类型转换：字符串列与数字比较
- 前导模糊查询：`LIKE '%abc'`
- OR 连接非索引列
- 联合索引未遵循最左前缀

### 事务与隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|:----:|:---------:|:----:|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不会 | 可能 | 可能 |
| REPEATABLE READ（MySQL 默认） | 不会 | 不会 | 可能（InnoDB 通过 MVCC+间隙锁基本解决） |
| SERIALIZABLE | 不会 | 不会 | 不会 |

- MVCC：事务快照（undo log + 版本链 + ReadView），实现读写不互斥
- 锁：行锁 / 间隙锁 / 临键锁、乐观锁（版本号）vs 悲观锁

### SQL 优化流程

1. `EXPLAIN` 看执行计划：type、key、rows、Extra
2. 避免全表扫描：检查是否走索引
3. 只查需要的列，避免 `SELECT *`
4. 大分页优化：`LIMIT 100000, 20` → 用 `WHERE id > ?` 或游标分页
5. 慢查询日志定位慢 SQL

## 缓存（Redis）

### 三大经典问题

| 问题 | 场景 | 解决方案 |
|------|------|---------|
| 缓存穿透 | 查询不存在的 key，打到数据库 | 缓存空值（TTL 短）、布隆过滤器 |
| 缓存击穿 | 热点 key 过期瞬间，大量请求打库 | 互斥锁重建、逻辑过期 |
| 缓存雪崩 | 大量 key 同时过期，或 Redis 宕机 | 过期时间加随机值、多级缓存、限流降级 |

### 分布式锁

```python
# Redis 分布式锁（SETNX + 过期时间 + Lua 释放）
import redis
r = redis.Redis()

# 加锁：SET key value NX EX ttl
ok = r.set('lock:order', 'unique-id', nx=True, ex=10)

# 释放：Lua 保证「判断持有者 + 删除」的原子性
lua = """
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
else
    return 0
end
"""
r.eval(lua, 1, 'lock:order', 'unique-id')
```

## 缓存一致性

**写策略**（更新数据库 + 删除缓存）：

1. 先更新数据库，再删除缓存（主流，配合延迟双删处理并发）
2. 先删缓存，再更新数据库（失败率更高）
3. 最终一致性兜底：消息队列重试、定时任务对账
