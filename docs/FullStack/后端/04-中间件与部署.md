# 中间件与部署

## 消息队列（Kafka / RabbitMQ）

### 应用场景

1. **异步解耦**：订单创建后发消息，后续服务异步消费
2. **削峰填谷**：秒杀流量先入队，下游按自身能力消费
3. **最终一致**：跨服务数据同步，配合本地消息表

### 核心概念

| 概念 | 说明 |
|------|------|
| Producer / Consumer | 生产者 / 消费者 |
| Broker | 消息服务器 |
| Topic / Partition | 主题 / 分区（并行度与顺序性的权衡） |
| Offset | 消费者消费位置 |
| ACK | 消费确认机制（手动 ack 保证不丢） |

### 可靠性三问（高频面试）

| 问题 | 方案 |
|------|------|
| 消息不丢 | 生产端 ack 确认 + 分区副本（replica）+ 消费端手动 ack |
| 消息不重复 | 消费幂等（唯一业务号 + 去重表） |
| 消息有序 | 单分区单消费者，或按业务 key 路由到固定分区 |

### RabbitMQ vs Kafka

| | RabbitMQ | Kafka |
|---|---|---|
| 定位 | 通用消息中间件 | 分布式流平台 |
| 吞吐 | 中等 | 极高 |
| 消息模型 | 交换机/队列路由 | 分区日志（可回溯） |
| 适用 | 业务解耦、灵活路由 | 大数据量、日志、事件流 |

## 搜索（Elasticsearch）

- 倒排索引：词 → 文档，实现全文搜索
- 核心概念：索引/文档/分片/副本、分词器（IK 中文分词）
- 与数据库同步：canal 监听 binlog → MQ → ES
- 查询：match（分词匹配）vs term（精确匹配）、聚合分析

## Docker

```dockerfile
# 示例：Spring Boot 应用镜像
FROM eclipse-temurin:17-jre
COPY app.jar /app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

- 镜像 vs 容器：镜像只读模板，容器是运行实例
- 核心命令：`docker build/run/ps/exec/logs`、`docker-compose` 编排多服务
- 网络与数据卷：容器间通信、数据持久化

## 部署与运维

### Linux 基础

- 常用命令：`ps`、`top`、`netstat`、`curl`、`systemctl`、`tail -f`
- 排查流程：CPU 高 → top 定位进程 → 线程栈；磁盘满 → df/du；连接数 → ss/netstat

### Nginx

- 反向代理 + 负载均衡（upstream、轮询/权重/ip_hash）
- 静态资源服务与缓存配置
- HTTPS 配置、`location` 路由规则

### CI/CD

```
代码提交 → 触发流水线 → lint/测试 → 构建镜像 → 推送仓库 → 部署到服务器
```

- GitLab CI / GitHub Actions / Jenkins
- 蓝绿发布 / 金丝雀发布 / 滚动更新

### 可观测性（三件套）

| 维度 | 工具 |
|------|------|
| 日志 Logging | ELK / Loki |
| 指标 Metrics | Prometheus + Grafana |
| 链路追踪 Tracing | Jaeger / SkyWalking |

## 云原生方向

- K8s：Pod、Deployment、Service、Ingress、HPA 自动伸缩
- Service Mesh：Istio 服务治理
- Serverless：按需运行，免运维
