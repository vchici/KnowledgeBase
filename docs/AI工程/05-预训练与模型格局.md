# 预训练与模型格局

> **本质**：预训练 = 在数万亿 token 上做自监督的 next-token-prediction，把语言规律和世界知识**压进参数**。之后的所有工作（SFT、RLHF）都只是教会模型「怎么用」这些知识。

## 核心考点

### 1. 预训练流水线（工程视角）

```
海量数据（网页/代码/书/论文）
  → 清洗（质量过滤、去重、去有害内容）——数据质量决定模型上限
  → 配比（代码占比高 → 推理能力强）
  → Tokenize → 大规模分布式训练（数周~数月，万卡级）
```

### 2. 训练目标

- **Causal LM（因果语言模型）**：predict next token，主流唯一选择（GPT/LLaMA/Qwen 全是）。
- MLM（BERT 式完形填空）：已被生成范式淘汰，仅存于 Embedding 模型。
- 每个 token 都是一个监督信号 → 数据效率极高，这是 scaling 能成立的前提。

### 3. Scaling Laws（面试常考概念题）

- **Kaplan 定律**：模型能力随参数/数据/算力的增长**平滑可预测**地提升（loss 幂律下降）。
- **Chinchilla 修正**：给定算力，参数量与训练数据应**等比扩展**（约 20 tokens/参数）。教训：早期模型普遍「参数过大、数据喂少了」。
- **涌现能力**：小模型没有、规模跨过阈值后突然出现的能力（如指令跟随、复杂推理）。是否「真涌现」有争议（可能是度量不连续），但面试按现象描述即可。

### 4. MoE 混合专家（必考新热点）

- 思路：把 FFN 拆成多个「专家」，每个 token 由 Router 只激活少数几个（如 8 选 2）。
- **收益**：参数量大（知识容量大）但推理 FLOPs 小（只算激活的部分）。DeepSeek-V3（671B 总参 / 37B 激活）。
- 代价：训练不稳、显存要装下全部参数（专家并行的负载均衡问题）。

### 5. 模型格局速记（2025 视角，面试能报出名字和定位即可）

- **闭源第一梯队**：GPT-4o/o1（OpenAI）、Claude（Anthropic，长文本与 Agent 强）、Gemini（Google，多模态+超长上下文）。
- **开源主力**：LLaMA-3（Meta 基座标杆）、**Qwen 系列**（阿里，中文+多尺寸全）、**DeepSeek V3/R1**（性价比与推理模型惊艳）、GLM（智谱）、Mistral（欧洲小而美）。
- **推理模型**：o1 / DeepSeek-R1 —— 用 RL 训出长思维链，答题前先「想」，数学代码大幅提升，延迟和成本换质量。

### 6. 参数量与显存的换算（工程必背）

- **FP16/BF16 ≈ 2 bytes/参数 → 7B 模型权重 14GB**，INT8 减半，INT4 再减半（≈3.5GB）。
- 推理总显存 = 权重 + **KV Cache** + 激活 → 详见 [07-解码策略与推理基础](07-解码策略与推理基础.md)。

### 7. 上下文长度

- 演进：2K → 128K → 1M。技术支撑：RoPE 外推（YaRN/NTK）、FlashAttention、滑窗/稀疏注意力。
- 工程认知：**「支持 128K」≠「128K 内表现一样好」**——存在 lost-in-the-middle 现象，关键信息放头尾更稳。

### 8. 多模态 LLM（了解思路即可）

- 通用架构：视觉编码器 ViT（把图切块当 token）+ 连接层（投影/交叉注意力）+ LLM。代表：LLaVA（开源经典思路）、GPT-4o（原生多模态）。

## 面试高频速答

### 7B 模型推理需要多少显存？

<details>
<summary>答案</summary>
FP16 权重 14GB + KV Cache（随上下文和并发线性增长）+ 少量激活，实际留 18-20GB 起步；INT4 量化后权重约 3.5GB，消费级显卡可跑。KV Cache 算法：2 × 层数 × KV头数 × head_dim × 序列长 × batch × 每元素字节数。
</details>

### MoE 为什么能「大而便宜」？

<details>
<summary>答案</summary>
知识容量由总参数决定（全部 FFN 专家），单 token 计算量只由激活的专家决定（Router top-k 路由）。相当于「图书馆很大，但每次只翻两本书」。
</details>
