# LoRA 原理

> **一句话**：LoRA 不直接改原模型的大权重，而是额外挂两个「小矩阵」A、B 来学微调时的变化量，训完再把它们并回原权重。用一个低秩的 ΔW 近似全量微调的更新量，显存和算力省下 99%。

## 直白版：老员工 + 小本子

把模型想成一个已经「身经百战」的老员工（预训练好的权重 W₀）。现在要让他适应新业务（微调）。

- **全参微调** = 从头重新培训他所有技能：又贵又慢，还容易把老本行忘掉（灾难性遗忘）。
- **LoRA** = 老员工的本事一点不动（W₀ 冻结），只给他配一个「小本子」记录要改的增量。训练时只改小本子，训完把小本子里的东西并进大脑（合并回 W₀），他就同时会了新旧两种本事。

这个「小本子」就是两个小矩阵 A 和 B。

## 数学形式（必背）

微调后的权重：

```
W' = W₀ + ΔW = W₀ + B · A
```

- `W₀`：原权重，训练时**冻结**不动。
- `A ∈ R^{r×d}`：降维矩阵，把 d 维压到 r 维。
- `B ∈ R^{d×r}`：升维矩阵，把 r 维再映射回 d 维。
- `r`：秩（rank），远小于 d，常取 8~64。

> 关键：ΔW 用 B·A 两个低秩矩阵的乘积表示，参数量从 d×d 降到 d×r + r×d；r ≪ d 时可训参数占比 < 1%。

## 为什么有效（低秩假设）

LoRA 的立论基础：**微调引起的权重变化 ΔW 是「低秩」的**——任务适应不需要在每个维度上都动刀，只在少数几个关键方向上调整就够。

类比：学会「客服话术」不需要重写模型里每一个神经元，只需在少数几个「方向」上微调。这些方向构成一个低维子空间，用秩 r 的矩阵就足够刻画。

## rank 和 alpha 怎么选

- **rank (r)**：控制 ΔW 的表达能力。
  - 格式对齐 / 简单任务：r = 8~16。
  - 领域迁移重、数据多：r = 32~64+。
  - 经验：先小 r 跑通，不够再加大。
- **alpha**：缩放系数，实际缩放因子 ≈ alpha / r，常设 alpha ≈ 2r。

## 两个落地要点

- **只训 A/B**：可训参数 < 1%，梯度 / 优化器状态开销大幅下降。
- **推理零额外延迟**：训练完把 BA 合并回 W₀（merge），推理时和原模型一样快；也可以不合并，一套底座挂 N 个 adapter 热切换（多租户省钱）。

## QLoRA：更省的变体

底座模型量化到 4bit（NF4 类型）+ 再加 LoRA，单张 24G 显卡就能微调 33B 级模型，个人 / 小团队标配。
