# RAG 系统 ★

> **本质**：给 LLM 外挂一个「开卷考试」系统——先从外部知识库**检索**相关内容，塞进上下文再**生成**。解决参数知识的三大缺陷：**过时、不含私有数据、幻觉不可溯源**。

## 核心考点

### 1. 标准流程（必须能徒手画）

```
离线：文档加载 → 切分(chunk) → Embedding → 向量库
在线：query → (改写) → 检索 top-k → rerank → 拼 prompt → LLM 生成(带引用)
```

- 每个环节都是可插拔的优化点——**RAG 调优 = 对每个环节做诊断**。

### 2. 为什么用 RAG（vs 微调，必考）

- 知识**随时更新**（改文档即生效，微调要重训）。
- **可溯源**（给引用，可审计，幻觉代价低）。
- **成本低**（无需训练，十几分钟搭起来）。
- 缺点：受检索质量上限约束、长文档塞 prompt 有 token 成本（→ [10.1-长文档Token成本优化](10.1-长文档Token成本优化.md)）、多跳推理弱（→ [10.2-多跳推理](10.2-多跳推理.md)）。

### 3. 切分策略（工程第一坑）

- **固定长度 + overlap**：简单基线，chunk 300-800 token、overlap 10-20%。
- **按结构切**：Markdown 标题/段落/代码块边界——尊重语义单元。
- **语义切分**：句子向量相邻相似度骤降处切开。
- **核心权衡**：chunk 太小 → 上下文不完整；太大 → 噪声稀释关键信息 + 检索粒度粗。**没有银弹，用评测集调。**
- 元数据：切分后的 chunk 进向量库时不只存「正文 + 向量」，还挂上一组source/标题/时间/权限标签 → 支持过滤（权限、时效）和溯源（知识库运维）。

### 4. 检索策略进阶（按问题对症下药）

| 问题 | 对策 |
|------|------|
| query 写得差、口语化 | **查询改写**：让 LLM 重写/扩展多查询；**HyDE**：先让 LLM 生成假想答案，再用假想答案当检索探针匹配（多一次LLM调用的成本，延迟；LLM对陌生领域生成的假答案可能带偏检索） |
| 字面匹配失效（型号/代码） | 混合检索 + RRF（→ [09-Embedding与向量检索](../09-Embedding与向量检索.md)） |
| 排序不准 | Rerank（Cross-Encoder） |
| 小块检索准但信息碎 | **父文档检索**：用小块做匹配，返回其所属大块/整节 |
| 多轮对话指代（"它怎么收费？"） | **问题改写**：结合历史把指代补全成独立问题 |
| 只想搜某类文档 | 元数据过滤（先过滤后向量检索） |

### 5. 进阶架构（名词 + 适用场景）

- **GraphRAG**：从文档抽实体关系建图谱，回答**全局性/汇总性**问题（"这批文档的主要主题"）——向量检索天然只会「局部片段匹配」（原理与代价详见 [10.2-多跳推理 · 解法一](10.2-多跳推理.md#解法一：GraphRAG)）。
- **Agentic RAG**：让 Agent 决定**要不要检索、检索哪个库、够不够要不要再搜**（工作流详见 [10.2-多跳推理 · 解法二](10.2-多跳推理.md#解法二：Agentic%20RAG)；→ [13-Agent架构](../13-Agent架构.md)）。
- **多模态 RAG**：表格/图片/版面用多模态模型或 OCR+caption 处理。

### 6. RAG 评估：RAGAS 三件套（必背）

分模块评估，先定位「检索错」还是「生成错」：

- **Context Precision**：检索回来的内容里有多少是相关的（检索准不准）。
- **Context Recall**：该检到的有没有检到（需要标注参考答案，检索全不全）。
- **Faithfulness（忠实度）**：答案是否忠于检索内容（**幻觉率**的代理指标）。
- **Answer Relevancy**：答案是否切题。

### 7. 幻觉治理（工程态度）

- Prompt 约束：「仅依据以下资料回答，资料中没有就说没有」。
- 引用溯源：答案标注 [1][2]，前端可点开原文。
- rerank 收紧噪声、生成后用小模型/规则做一致性校验。
- **无法根除，只能压低 + 兜底话术 + 人工兜底**，这是面试时成熟的表达。

### 8. 常见工程坑（实战谈资）

切分把表格/代码切碎；embedding 模型与文档语言不匹配；知识库更新忘了重建索引；检索永远返回同样内容（query 太通用）；top-k 塞满 prompt 反而掉点（lost in the middle）。

## 面试高频速答

### RAG 效果差，怎么排查？

<details>
<summary>答案</summary>
先分锅：看检索层——把 top-k 内容打出来人工核对，该召回没召回 → 查切分/embedding/混合检索/查询改写；召回了但排序差 → 上 rerank。再看生成层——内容给了但答错 → 查 prompt 约束、模型能力、上下文是否过长。用 RAGAS 或自建评测集量化每一步改动。
</details>

### RAG 和微调怎么选？

<details>
<summary>答案</summary>
知识类需求（文档问答、时效性、要溯源）→ RAG；行为类需求（固定格式、语气、领域指令跟随）→ 微调；两者正交，生产上常组合：RAG 管知识 + 轻量微调管行为。参考 [06-微调与对齐](../06-微调与对齐.md)。
</details>
