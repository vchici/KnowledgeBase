# LLM 应用工程实践 ★

> **本质**：AI 应用工程 = 把一个**概率性、会出错、按 token 收费**的模型，做成**可控、可评、可省**的在线服务。本篇是前面所有章节的收口：怎么选型、怎么省钱、怎么评估、怎么兜底。

## 核心考点

### 1. 技术选型决策树（必考，背下来）

```
需求明确了？
 ① 先用最强模型 + 好 Prompt 跑基线（别急着造系统）
 ② 知识不够 / 会过时 / 要溯源 → RAG
 ③ 行为不稳 / 格式乱 / 领域风格差 → SFT(LoRA) / DPO
 ④ 单次调用不够 → 工具调用 → 复杂任务才上 Agent
 ⑤ 每加一层复杂度，先问：评测集证明它值得吗？
```

- 反向原则：**能用简单方案解决的，绝不引入 Agent**（成本、延迟、调试难度全面上升）。

### 2. 模型分级与路由（成本第一杀器）

- 请求分类 → 简单任务路由到小模型/便宜模型，难的才给旗舰模型。
- 实现层级：规则路由（长度/关键词）→ **小模型分类器** → LLM 自路由（self-route：先小模型，置信度低升级）。
- 数字直觉：小模型成本可为旗舰的 1/50 ~ 1/100，多数流量其实不需要最强模型。

### 3. 缓存（成本第二杀器）

- **精确缓存**：同请求命中缓存（prompt 规范化后 hash）。
- **语义缓存**：embedding 相近的请求命中（阈值要保守，误命中比不命中更糟）。
- **Prefix Cache**：system prompt/few-shot 固定部分的服务端 KV 复用（API 按 cached token 计费打折；自建见 [08-推理优化与部署](08-推理优化与部署.md)）。

### 4. 延迟优化清单

- 流式输出（体验优化之王，TTFT 感知）；生成越短越快（约束输出长度）；
- 并行化：无依赖的多个调用并发；「先流式输出框架、再填充细节」；
- 模型小、量化、推测解码（自建）；prompt 瘦身（历史摘要压缩）。

### 5. 评估体系（LLM 应用的核心难题，必考大题）

- **离线评测集（golden set）**：几十到几百条代表性 case + 期望，每次改动跑回归。**没有评测集的 Prompt/系统调优都是玄学。**
- **LLM-as-Judge**：用强模型按 rubric 打分。坑：位置偏差（偏爱某顺序）、自偏好（偏爱自家风格）、过度宽容 → 缓解：交换顺序、多评委、校准样例。
- **在线评估**：A/B 实验、用户反馈（点赞/点踩）、隐性信号（重试率、采纳率、改写率）。
- 分层评估：单点（模型/组件）→ 流水线（RAG 三件套，→ [10-RAG系统](10-RAG系统.md)）→ 端到端（任务成功率）。

### 6. 可观测性

- 全量记录：请求/响应、工具调用链、token 用量与成本、延迟分解（TTFT/TPOT）、错误与重试。
- trace 贯穿 Agent 每一步（→ [13-Agent架构](13-Agent架构.md)）；成本与质量看板 + 异常告警。
- 工具族：LangSmith / Langfuse / Phoenix（思路一致：trace + 评测 + 数据集）。

### 7. 安全与合规（生产必答题）

- **输入侧**：prompt 注入防御（→ [11-Prompt工程](11-Prompt工程.md)）、敏感数据脱敏（PII 不出域）。
- **输出侧**：有害内容过滤、越狱测试、结构校验。
- **权限**：工具最小授权、危险操作人工确认、沙箱执行。
- **合规**：用户数据发给三方 API 的协议问题、日志留存策略、模型输出的免责声明。

### 8. 幻觉的工程态度（面试表达模板）

「无法根除，只能系统化管理：RAG 提供事实依据 + 引用溯源 + 忠实度校验 + 检索不到时的兜底话术 + 高风险场景人工审核。」——展示的是**分层治理思维**，不是一句"加个 RAG"。

## 面试高频速答

### 成本太高怎么降？

<details>
<summary>答案</summary>
按顺序：路由分级（大模型只接难任务）→ 缓存（精确/语义/prefix）→ prompt 瘦身与历史压缩 → 输出长度约束 → 自建量化推理（流量大到 API 单价不再划算时）。前提是先有按请求维度的成本观测，否则降无可降也不自知。
</details>

### 如何证明你的 LLM 应用「变好了」？

<details>
<summary>答案</summary>
离线 golden set 回归 + LLM-as-judge 按维度打分（忠实度/相关性/格式），上线后 A/B + 用户反馈闭环。强调每次改动前先建评测、改动后看分数，这是区分「调 prompt 玄学」和「工程」的分水岭。
</details>

### 给你一个新需求，怎么设计 LLM 方案？

<details>
<summary>答案</summary>
先拆需求：知识型（RAG）、任务型（工具/Agent）、生成型（prompt+格式约束）→ 用最强模型+简单方案建基线 → 建评测集 → 逐层加复杂度并用评测证明每一层收益 → 上线接观测（成本/质量/反馈）→ 迭代。
</details>
