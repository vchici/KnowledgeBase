# UMA 统一内存:为什么"共享内存"还要拷贝

> **本质**:UMA 让手机 CPU/GPU 共用一颗内存，省掉了"跨总线搬运";但 Bitmap 像素交给 GPU 采样，仍要一次内存内拷贝。**省了搬楼，没省复印。**

## 总线:PC 上的搬运高速路

- PC 独显:GPU 有自己的显存，和 CPU 内存之间靠 **PCIe 总线**传数据。
- CPU 内存里的数据要给 GPU 用，必须经 PCIe 物理搬一趟——又慢又贵。

## UMA:手机上的共享内存

- 手机 CPU 和 GPU **共用同一颗 LPDDR**，没有各自的内存。
- 不存在"从内存 A 芯片搬到内存 B 芯片"，所以不用跨总线。

## 但拷贝还在

物理内存是同一颗，可两边的**内存组织方式不同**:

```text
Bitmap 像素数组                GPU 纹理内存
malloc 的普通内存       ────►  驱动为 GPU 准备的内存
线性排布、归 GC 管              GPU 要求的排布(tiling)、生命周期独立
```

- GPU 不能直接拿线性数组采样，要按它要求的排布重新组织;
- 纹理内存生命周期独立于 GC，Bitmap 被回收也不影响它;
- 所以驱动把 48MB **逐字节 memcpy** 过去——15GB/s 带宽下 ≈3.2ms。

## 跳过拷贝的办法

- **HARDWARE Bitmap**(Android)/ 硬件解码(鸿蒙):解码时直接写进 GPU 可用内存，拷贝这步整个消失。
- 图变小，拷贝时间按比例缩 → [大图对于性能的影响](大图对于性能的影响.md)。
