# 组件创建、复用与更新的性能瓶颈

> **本质**:组件的耗时集中在三步——**创建**贵在建节点和测量布局，**复用**解决反复创建，**更新**贵在状态变化牵连的组件范围。列表卡顿基本是创建和更新叠加的结果。

## 全景流程

```mermaid
flowchart LR
    A["1 创建<br/>建节点 + 属性 + 测量布局"] --> B["2 复用<br/>滚动时从复用池取, 免重建"] --> C["3 更新<br/>状态变化 → 按依赖精准刷新"]
```

## 1 创建:每个新组件都要过一遍全流程

**干了什么**:实例化 JS 对象、`aboutToAppear`、创建 C++ 节点、设置属性、measure/layout、首帧绘制。列表一次滑入几十个 item，这些全堆在一帧(16.6ms)内。

**瓶颈**:

- **aboutToAppear 里做耗时活**:aboutToAppear 是组件上屏前必经的回调，里面同步读写文件、解析大 JSON、等网络，都得等它做完组件才显示，直接拖慢这一帧。
- **层级太深**:每套一层，系统就多算一轮"每个东西多大、摆在哪"。嵌套 5 层，这套计算就跑 5 遍。
- **用了 Flex**:[Flex 要先按内容量一遍、再按对齐方式量一遍](Flex与Row、Column的区别.md)，测量跑两轮。不需要换行就用 Column/Row，只量一遍。
- **ForEach 全量创建**:ForEach 把列表数据一次全建成组件，一万条就建一万个；LazyForEach 只建屏幕里的，`cachedCount` 再多备几条屏外的。
- **轻内容用了自定义组件**:自定义组件是一个自带状态和刷新逻辑的类，系统要为它单独记账；纯展示的重复片段用 @Builder——它只是个生成界面的函数，不多建任何东西。

## 2 复用:只在滚动场景生效

**干了什么**(@Reusable):item 滑出屏幕不销毁，进复用池；同类组件滑入直接取出，走 `aboutToReuse` 刷新数据，跳过建节点和测量。

**瓶颈**:

- **没开复用**:滑出屏幕的 item 直接销毁，滑回来再重建一遍。快速滑动就是不停地建、不停地销毁，内存回收也跟着不停触发。
- **aboutToReuse 里做重活**:复用只省了"建组件"这一步，数据还得重新刷。要是在 aboutToReuse 里解码大图、复制大对象，等于白复用。
- **条件不满足等于白标**:标了 @Reusable 也得配合 LazyForEach 才生效，而且只在同一种组件之间互相借。

## 3 更新:状态变化牵连多大范围

**干了什么**:状态变量变化 → 框架沿依赖找到关联组件 → 只重建受影响的分支。牵连范围由你的状态设计决定。

**瓶颈**:

- **@Prop 深拷贝**:@Prop 把父组件的数据完整复制一份给自己，数据大就拷得慢；改用 @ObjectLink 不复制，父子共用同一份数据(数据类要标 @Observed，改动才能被看见)。
- **一个状态绑定一大片**:状态变量挂在父组件顶层，几十个子组件都用了它，一变全体刷新。把变量挪到真正用到它的那个子组件里。
- **build 里调函数**:`Text(this.calc())` 组件每刷一次就重算一遍 calc，状态变得频繁就是每帧重算。
- **高频事件里改状态**:触摸、滚动回调里直接改 @State，每改一次就刷新一轮；连续变化用 animateTo，让系统自己算中间值，整个动画不触发状态刷新。
- **@Watch 里再改状态**:@Watch 是"状态变了叫我"的回调，回调里又改别的状态，就接着触发下一轮刷新；两个状态互相改，就刷个不停。
- **滥用 @StorageLink/@AppStorage**:这俩是全应用共用的变量，一变，所有用到它的组件全刷，不管在哪个页面。

## 速查

| 阶段 | 瓶颈 | 治法 |
| --- | --- | --- |
| 创建 | aboutToAppear 耗时活 | 异步/延迟 |
| 创建 | 层级深、用 Flex | 少嵌套，Column/Row 优先 |
| 创建 | ForEach 全量建 | LazyForEach + cachedCount |
| 复用 | 未开复用 | @Reusable + LazyForEach |
| 复用 | aboutToReuse 重活 | 只做数据赋值 |
| 更新 | @Prop 深拷贝 | @ObjectLink |
| 更新 | 状态牵连过宽 | 状态挪到用的组件里 |
| 更新 | 高频改状态 | animateTo/属性动画 |

## 一句话总结

创建治"别建那么多"——LazyForEach 加复用；更新治"别刷那么宽"——状态拆小加 @ObjectLink。
