# 09-向量数据库与AI演进

> 一句话本质：向量数据库把「语义相近 ⇔ 向量距离近」变成可查询的索引（ANN），Agent 时代数据库的四条演进主线——向量化、图谱化、记忆冷热分离、长文本存储优化——都围绕 AI 密集型读写重构。

至此（[01-数据库架构](./01-数据库架构.md) ~ [08-任务状态与崩溃恢复](./08-任务状态与崩溃恢复.md)）讲的都是传统关系库；本篇看 AI 时代数据库的扩展与演进。过去面试必问索引、事务，现在面 Agent 或 AI 基础架构，必问**向量数据库**和**知识图谱**——它们是 Agent 解决幻觉（Hallucination）、实现 RAG 的基石。

## 一、向量数据库是什么

存储并检索**高维向量**的数据库。常用产品：Pinecone、Milvus、Weaviate、Chroma、Qdrant、Faiss，以及 Postgres 扩展 **pgvector**（数据已在 PG 时可少一个组件）。

与传统数据库对比：

| 维度 | 传统数据库 | 向量数据库 |
|------|-----------|-----------|
| 查询类型 | 精确匹配、范围查询 | 相似度搜索（**ANN**） |
| 索引结构 | B+ 树、哈希（见 [02-数据库索引](./02-数据库索引.md)） | HNSW、IVF、PQ |
| 查询方式 | `WHERE id = 1` | `query(vector, top_k=10)` |
| 返回结果 | 完全匹配的记录 | 最相似的 k 个向量 |
| 存储对象 | 结构化数据 | Embedding 向量 |

以 Chroma 为例的落盘结构：元数据、文档放 `chroma.sqlite3`，向量放 `index/<collection>/hnsw.index`——**结构化部分仍用关系库，向量部分交给专门的 ANN 索引**。

## 二、ANN：近似最近邻搜索

Approximate Nearest Neighbor——**牺牲少量精度，换取大幅查询提速**：不遍历所有向量，而是通过索引结构快速定位可能相似的候选集。典型算法：

- **HNSW**：层次化可导航小世界图（主流默认）
- **IVF**：倒排索引分桶
- **PQ**：乘积量化压缩

Embedding 侧的配套概念：**Embedding 是把文本/图像转成固定长度的数值向量**，向量在高维空间表达语义，相似内容距离近。什么时候需要向量库：语义搜索、RAG 检索知识库、推荐系统找相似内容、聚类分析去重。

## 三、Agent 时代数据库的四大演进方向

传统数据库按"人类用户行为模式"设计（读多写少、有波峰波谷）；Agent 是 **AI 密集型客户端**——超高频思考链路记录（Thought Trajectory）、长文本上下文、24 小时不知疲倦的高并发读写。八股考点随之更新：

| 传统必问 | Agent 时代必问 |
|---------|---------------|
| MySQL 索引底层原理（B+ 树） | **向量索引底层原理与 ANN** |
| 多表 Join 性能优化 | **Graph RAG 如何解决长文本与复杂实体关系推理** |
| 冷热数据分离（旧订单移入 ClickHouse） | **Agent 短期记忆 / 长期记忆的存储架构设计** |
| 为什么不建议 MySQL 存 TEXT/BLOB（行溢出拖累 B+ 树页效率，见 [07-字段与表设计](./07-字段与表设计.md)） | **反思日志、Tool 返回值这种庞大 JSON 怎么存** |

两个重点展开：

- **Graph RAG**：向量检索擅长"语义相似"，但长文本里**多跳实体关系**（A 的上级负责的项目依赖哪些系统）靠 embedding 召回容易丢链路；把实体和关系抽成知识图谱，图遍历 + 向量召回结合，解决复杂实体关系推理。
- **记忆冷热分离**：短期记忆（当前对话上下文）高频读写、生命周期短，放热存储；长期记忆（沉淀的事实、偏好）低频访问，落向量库/图数据库做检索——就是传统冷热分离思路在 Agent 记忆架构上的翻版。

## 面试问答

### 向量数据库和传统数据库的核心区别？

<details><summary>参考答案</summary>
查询语义不同：传统库做精确匹配/范围查询（WHERE），返回完全匹配的记录，靠 B+ 树/哈希索引；向量库做相似度搜索，query 给一个向量取 top_k，返回最相似的 k 条，靠 HNSW/IVF/PQ 这类 ANN 索引。共同点是元数据、过滤条件仍可用关系结构管理（如 pgvector 直接是 Postgres 扩展，Chroma 的元数据也在 sqlite3 里），向量部分才走专门的 ANN 索引。
</details>

### 什么是 ANN？为什么需要它？

<details><summary>参考答案</summary>
Approximate Nearest Neighbor，近似最近邻搜索。海量高维向量下暴力精确检索是 O(N) 不可行，ANN 通过索引结构（HNSW 分层图、IVF 倒排分桶、PQ 量化压缩）快速圈出候选集，牺牲少量召回精度换数量级的速度提升。依赖的前提是 Embedding 把语义相近的内容映射到距离相近的向量。
</details>

### Agent 时代数据库设计要更新哪些认知？

<details><summary>参考答案</summary>
四个方向：① 向量化——向量索引与 ANN 成为基础考点，支撑语义检索与 RAG；② 图谱化——Graph RAG 用知识图谱补足向量检索在多跳实体关系推理上的短板；③ 记忆冷热分离——短期记忆（会话上下文）放热存储，长期记忆落向量库/图库，对应传统冷热分层；④ 长文本/JSON 存储优化——Agent 的反思日志、Tool 返回值是庞大 JSON，要重新权衡 TEXT 行外存储、JSON 类型与压缩归档，而不是照搬"别在 MySQL 存 TEXT"的旧结论。
</details>
