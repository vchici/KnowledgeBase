# 幂等、重试与补偿

> 定位：事务只保证**单个库、一组操作**的原子回滚（见[数据库事务](./数据库事务.md)）。长流程拆成多个小事务后，中间隔着崩溃重启、重试重投，"部分成功"的中间态没法靠一个大事务兜底——工业界的组合拳是**重试 + 幂等 + 补偿**三件套，终点是**最终一致**而不是强一致。

## 一、为什么单靠事务不够

- 事务的原子性边界 = 一次 `commit`。事务里放 RPC / 文件 I/O 会长期持锁，所以长流程必然拆成多个小事务（原则见[数据库事务](./数据库事务.md)第五节）
- 小事务各自成功或失败，组合出**部分成功**：第 3 段失败了，前 2 段已经落库，回不去
- 此时能用的手段只有三个方向：**重来一次**（重试）、**重复来了也无害**（幂等）、**撤销已做的**（补偿）

## 二、幂等：让重复执行无害

定义：同一操作执行一次和执行 N 次，效果相同。

为什么必须有：重试和 MQ 至少一次投递（见[消息队列](./Redis/消息队列.md)）意味着**重复是常态不是异常**；崩溃恢复的「重跑」也靠它兜底（见[任务状态与崩溃恢复](./任务状态与崩溃恢复.md)）。

| 实现 | 原理 | 适用 |
|------|------|------|
| 唯一索引 / 唯一键 | 数据库层面拒绝重复插入（如结果表 `task_id`） | 插入类，**最可靠**，兜底永远在 DB |
| 状态机校验 | 只有合法状态才流转，`UPDATE ... WHERE status='PENDING'` 更新到 0 行即被人抢先 | 任务 / 订单执行 |
| 乐观锁版本号 | `UPDATE ... SET v=v+1 WHERE v=?`，只让一个请求生效 | 更新类 |
| 天然幂等 | `DELETE by id`、`UPDATE 固定值` | 本来就安全，无需设计 |
| Token / Idempotency-Key | 先领号、执行时核销 | 前端防重复提交、接口层 |

坑：**先查后插有竞态**——查的时候不存在、插入时别人已经插了。唯一索引 + 捕获冲突错误才是原子判断。

## 三、重试：对付瞬时失败

先把失败分类：

| 类型 | 例子 | 处理 |
|------|------|------|
| 瞬时失败 | 网络抖动、锁冲突、临时不可用 | 自动重试能好 |
| 永久失败 | 参数非法、数据格式错 | 重试多少次都没用，快速失败进失败列表 |

重试的三个关键参数：

1. **次数上限**：超过 N 次进死信 / 失败列表（人工介入或定时补偿），不能无限循环
2. **退避**：指数退避 + 随机抖动，不要固定间隔
3. **前提幂等**：只重试幂等操作，否则重试 = 制造重复数据

重试风暴：下游抖一下，所有上游同时重试，流量放大数倍直接压垮下游 → 退避 + 抖动缓解，配合熔断限流（见[系统设计与架构](../FullStack/后端/03-系统设计与架构.md)）止血。

## 四、补偿：对付不能重试的失败

场景：流程走到第 N 步失败，前面 N-1 步已各自提交，回滚不了（不是同一个事务）。

做法：**不回滚，再执行一个反向操作把已做的抵消掉**。

- **Saga**：长事务拆成 `T1 → T2 → … → Tn` 一串本地事务，每个 Ti 配一个反向补偿 Ci；某步失败就逆序执行 C
- **TCC**：Try 预留资源 → Confirm 确认 / Cancel 释放。比 Saga 多一步「预留」，适合扣库存、冻结余额这类不能事后硬撤的场景
- **本地消息表 / 事务消息**：业务数据和「待办消息」同一事务落库，异步推进，消费端幂等兜底，通用业务最常用

规则要明确：失败后后续步骤是**中止**（逐段补偿）还是**跳过**（要有豁免理由、结果里可查询），必须事先定义，不能到现场再拍。

## 五、三件套怎么配合

一句话流程：

1. 失败 → 先判断瞬时还是永久
2. 瞬时 → 重试（退避），前提是操作幂等
3. 重试超限 → 死信 / 失败列表，人工或定时处理
4. 流程中途失败无法继续 → 补偿撤销已完成部分，后续按明确规则中止或跳过

对应工业组件：MQ = 至少一次投递 + 消费端幂等；任务系统 = 任务表重试 + 死信；跨服务 = Saga / TCC / 本地消息表（详见[系统设计与架构](../FullStack/后端/03-系统设计与架构.md)）。

本地单机场景（多段体检，见[项目包装-手机性能检测](../FullStack/项目包装-手机性能检测.md)）：一段的写入用真事务原子提交；跨段用任务表状态机驱动，失败自动重试 N 次、超限进失败列表，`task_id` 唯一索引保幂等，某段失败后中止 / 跳过——就是三件套的最小落地。
