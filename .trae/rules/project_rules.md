# KnowledgeBase 项目规则

> 本文件是项目的 AI 协作规则，每次会话自动加载。改这里即可生效，无需动 C 盘。

## Hard Constraints
- 技术笔记只保留核心结论和关键信息，直白简洁分点表述，适用所有技术主题
- 中文内容一律用中文标点
- 术语当场用大白话解释，零背景能读懂
- 用通用标准 markdown（标题/表格/代码块/标准链接/details 折叠），不用特定软件方言格式
- 前端展示同步：新增文档按目录编号规则命名，更新导读/互链确保入口可达；删除文档时清理失效链接
- 交付物一律放本项目目录内，禁止向 C 盘写入任何文件

## 算法笔记规范
- 所有算法题笔记以**状态演化/可视化**为主，完整代码不贴正文
- 状态演化用 `<details><summary>状态演化</summary>` 包裹，默认折叠，点击展开
- 可视化形式按题型匹配：双指针用演化表、DP 用填表 DAG、回溯用剪枝决策树、KMP 用对齐图
- 代码统一放 `docs/Algorithm/` 下对应的 `.java` 文件，笔记末尾用 GitHub blob 链接引用（格式：[文件名](https://github.com/vchici/KnowledgeBase/blob/main/docs/Algorithm/文件名.java) → 方法名）
- 演化表必须有具体示例（数组/字符串 + target），每步一行展示指针/状态怎么变

## Lessons Learned
- 大图性能优化的核心手段是让Bitmap尺寸等于显示尺寸，该手段可同时解决解码、内存、上传、采样四个环节的性能问题
- 网络大图仅靠客户端autoResize无法节省下载流量，需配合服务端/CDN按显示尺寸裁剪才能完整优化
- 沙箱图片属于本地图片，autoResize可正常生效；若沙箱图片由网络下载后存储，需在下载阶段就按显示尺寸获取小图，避免存储原图带来的额外成本
