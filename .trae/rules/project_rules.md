# KnowledgeBase 项目规则

> 本文件是项目的 AI 协作规则，每次会话自动加载。改这里即可生效，无需动 C 盘。

## Hard Constraints
- 技术笔记必须使用直白简洁的表述，分阶段/分点说明核心逻辑，禁止冗余发散和多余解释（适用所有技术主题，不限于 Android）
- 技术笔记需保留关键数字和核心结论，避免复杂的原理性展开
- 生成中文内容时标点一律用中文标点（逗号、句号等），不要用半角标点
- 技术文档中的术语解释必须简单直白，不能使用本身就需要进一步解释的词语，不能啰嗦也不能解释不清
- 所有 markdown 一律用通用标准语法，不使用特定软件的方言格式（如 wiki 链接、callout 等）
- 项目内容会在前端展示：每次新增或删除文档后，必须同步兼顾前端显示——新文档按目录现有编号规则命名（如 03-xxx.md），并更新所在目录的导读/索引或相邻文档的互链，确保前端有入口可达、无失效链接
- 交付物一律放本项目目录内，禁止向 C 盘写入任何文件

## Lessons Learned
- 大图性能优化的核心手段是让Bitmap尺寸等于显示尺寸，该手段可同时解决解码、内存、上传、采样四个环节的性能问题
- 网络大图仅靠客户端autoResize无法节省下载流量，需配合服务端/CDN按显示尺寸裁剪才能完整优化
- 沙箱图片属于本地图片，autoResize可正常生效；若沙箱图片由网络下载后存储，需在下载阶段就按显示尺寸获取小图，避免存储原图带来的额外成本
