工具分发

模型的调用意图 → 注册表匹配 → 参数校验 → 执行 → 结果回填。你的 dailyreport 以 12 个 MCP 工具挂在此层。

权限门控

deny → ask → allow 三级评估链，deny 永远胜出。dailyreport 目前缺失的一件。

上下文管理

决定什么进窗口：检索 top-k、历史截断、渐进式披露。dailyreport 的 8 轮上限与双路加权检索属于此件。

记忆

跨会话持久化（AGENTS.md / CLAUDE.md / data/*.json）。dailyreport 的 storage.py 已覆盖。

子任务编排

意图分发、子代理并行、结果汇总。dailyreport 的 auto_dispatch + text_parser 已覆盖。

Harness Effect

同模型、不同 harness 的表现差：Claude Opus 在 Cursor 93 vs Claude Code 77（Terminal-Bench 2.0）。

插件的目录结构

my-plugin/
  .claude-plugin/
    plugin.json        # 插件清单（至少含 name），让技能升级为插件
  skills/
    <skill-name>/
      SKILL.md         # 技能定义：YAML frontmatter + Markdown 正文
      references/       # 按需加载的详细资料（渐进式披露第三层）
  agents/               # 子代理定义（角色、I/O 协议）
  hooks/                # 生命周期钩子脚本

SKILL.md 最小模板（官方规范）

---
description: 一句话说明做什么 + Use when 触发条件。
  这是唯一常驻上下文的部分，要写「什么时候用我」。
---
## Instructions
正文：只在技能被触发时才加载。
可以用 !`命令` 语法注入动态上下文（执行命令、以输出替换该行）。

技能存放位置（三级）

级别路径作用范围
个人~/.claude/skills/<name>/SKILL.md你的所有项目
项目.claude/skills/<name>/SKILL.md仅当前项目
插件<plugin>/skills/<name>/SKILL.md启用插件处（带命名空间 name:skill）

可插拔阶梯（第 2 课）

层扩展方式扩展者写什么
L0 硬编码改源码Python，重新发版
L1 配置驱动改配置.env / config
L2 协议挂载实现标准协议独立程序（MCP server）
L3 声明式插件放文件Markdown + 清单

组件完备性（能干活）≠ 可插拔性（能被扩展）。Skill=条件知识（LLM 判断触发）；Hook=确定性代码（事件必执行）；plugin.json=身份证。

revfactory/harness 六种团队架构（选型用）

模式一句话典型场景
Pipeline 流水线A 的输出是 B 的输入设计→开发→测试→部署
Fan-out / Fan-in并行独立处理，结果聚合多维度代码审查
Expert Pool 专家池按上下文动态选一个专家多能力、非同时激活
Producer-Reviewer生成后自动触发审核闭环内容生产+质量把关
Supervisor 监督者中央协调、动态分发多环节创作统筹
Hierarchical 层级委派自顶向下递归拆解大型工程
