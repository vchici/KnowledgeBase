HARNESS 课程 · 第 1 课 / 约 12 分钟

Agent Harness：你已经建过一个，只是不知道它的名字

本课目标：建立 Model + Harness 的心智模型，并用它重新看清你的 dailyreport。
课程使命：把 dailyreport 升级为 AI 编程工具生态的一等公民 · 速查表：Harness 备忘单

一、先看一个 16 分的问题

同一个 Claude Opus 模型，跑 Terminal-Bench 2.0 基准测试：在 Cursor 里得 93 分，在 Claude Code 里得 77 分。模型权重一个字都没变——16 分的差距，全部来自模型之外的那层工程。这就是 2026 年被广泛讨论的 Harness Effect：换 harness 的收益，可以大到超过换一个模型。

二、公式与定义

Coding Agent=AI Model+Harness

这个公式由 Viv Trivedy 提出，2026 年 2 月经 HashiCorp 联合创始人 Mitchell Hashimoto 推广后成为社区共识。Harness（原意「马的挽具」）指包裹在模型外层的全部运行时工程：系统提示、工具注册与分发、权限、上下文管理、记忆、子代理编排。

「Harness 工程：每当发现 agent 犯了一个错，就花时间做一个工程方案，让它永远不再犯这类错。」 —— Mitchell Hashimoto

一个完整的 harness，通常由五大件组成（拆解详文）：

五大件回答的问题例子
工具分发模型「说」想读文件后，谁去真读？MCP 工具调用、Shell 执行
权限门控哪些操作放行、哪些要问用户？deny / ask / allow 三级评估
上下文管理什么进上下文窗口，什么被挡在外面？检索 top-k、历史压缩、渐进披露
记忆跨会话还记得什么？AGENTS.md / CLAUDE.md / 数据库
子任务编排大任务怎么拆、分给谁？意图分发、子代理并行
AHA 时刻 为什么模型再强也替代不了 harness？三个理由：① 模型没有操作系统权限（它只能输出文本，是 harness 把文本变成真实操作）；② 模型无法自我约束（代码逻辑不会被话术说服）；③ 单次推理有上限（长任务必须靠 harness 分片与压缩）。

三、你已经建过一个 harness：dailyreport

这是本课最重要的一节。把五大件往 dailyreport 上一贴——你会发现五个里你已经做了四个：

映射基于 dailyreport 真实源码（src/ 目录），非虚构示例。
Harness 五大件dailyreport 中的实现判定
工具分发 mcp_server.py 向 TRAE 暴露 12 个 MCP 工具（record_plan / record_done / search_entries / generate_report…），由 TRAE 这个大 harness 调度 已有
上下文管理 orchestrator.py 只保留最近 8 轮对话（README 原话：「避免历史过长稀释注意力」）；retriever.py 双路加权检索只取 top-k；解析用 temperature=0.3 求稳定 已有
记忆 storage.py 按日期持久化 JSON / Markdown（data/、reports/、plans/），跨会话可查 已有
子任务编排 text_parser.py 把输入解析成 intent / events / entities，auto_dispatch 分发到对应处理函数，且避免重复解析 已有
权限门控 几乎没有——任何输入都会被解析、存储、检索 缺失

换句话说：你上周写的「避免历史稀释注意力」，在社区里有个正式的名字，叫 harness engineering。你不是要「入门 harness」，你是要给自己的两个 harness（TRAE 与 dailyreport）补上缺失的部件。

注意 还缺两样东西，恰好都是「harness 插件」能补的：① 权限/自动化机制（hooks）——比如会话开始时自动查今日状态；② 技能（skills）——教 TRAE「什么时候、以什么姿势」调用你的 12 个工具。这正是本课程主线。

四、那「harness 插件」到底是什么

把 harness 的某个部件（技能、钩子、子代理定义）写成标准格式的文件、打包分发，就是 harness 插件。最小单位是一个带 YAML frontmatter 的 SKILL.md（官方规范，也是 跨工具开放标准）：

---
description: 记录工作进展到 dailyreport。
  Use when 用户提到完成了某项工作、想记录待办或生成日报。
---
## Instructions
调用 ai-dailyreport 的 record_done / record_plan / generate_report 工具，
把结果用两三句话反馈给用户。

关键机制是渐进式披露（progressive disclosure）：frontmatter 里的 description 常驻上下文（几十 token），正文只在被触发时加载。所以技能库可以很大而不占日常窗口——这与你在 retriever 里「只取 top-k」是同一个思想。

而 GitHub 上 4.5k star 的 revfactory/harness 是个「meta-factory」插件：你说一句 「build a harness for this project」，它自动做领域分析 → 选 6 种团队架构之一 → 生成 .claude/agents/ 和 .claude/skills/。它背后的 A/B 实验显示：同一模型，加 harness 配置后任务均分 49.5 → 79.3（+60%），且任务越难提升越大。

六、小结与下一步

本课三个新术语（理解后我会录入 术语表）：Harness（模型外层的运行时工程，公式 AI Model + Harness）、Harness Effect（同模型、不同 harness 造成的表现差距）、渐进式披露（元数据常驻、正文按需加载的上下文经济术）。
