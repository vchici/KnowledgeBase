插件解剖：可插拔到底指什么，代码写在哪

起因：一个好问题——「你说我四大件都做完了，那可插拔的插件呢？」
前置：第 1 课 · Agent Harness 概念 · 速查：Harness 备忘单

一、纠偏：两个独立的坐标轴

第 1 课的映射表说的是「组件完备性」——一个 harness 要做的五件事（工具分发、权限、上下文、记忆、编排），dailyreport 做了四件。但你问的是「可插拔性」——这个 harness 能不能被扩展。这是两个正交的维度：

浏览器类比：Chrome 的渲染引擎、JS 引擎是「组件」；Chrome 商店那一整套 manifest + 加载器 + 权限声明，才是「可插拔机制」。
组件完备吗？（能不能干活）可插拔吗？（能不能被第三方扩展）
Claude Code完备有（skills / hooks / agents / MCP 四类扩展点）
dailyreport四大件 + MCP 工具面没有——12 个工具硬编码在 mcp_server.py，编排逻辑写死在 orchestrator.py

所以准确的说法是：你造了一个 harness，但还没给它造「插件系统」。上一课说「都做完了」指的是前者，你的直觉指后者——两者都对，缺的是区分。

AHA 时刻 可插拔的本质 = 宿主预留扩展点 + 插件满足契约 + 宿主运行时加载。三样缺一不可：没有扩展点，插件没处安放；没有契约（manifest / 协议），宿主不认识插件；没有加载器，文件只是死文本。

二、可插拔阶梯：L0 → L3

「可插拔」不是开关，是阶梯。每上一级，扩展者需要的编程知识更少、但受宿主的约束更多：

层级扩展方式扩展者写什么dailyreport 现状
L0 硬编码改源码Python，重新发版内部功能在这层（record_done 等函数本体）
L1 配置驱动改配置.env / config 文件.env 换模型、换 Key 在这层
L2 协议挂载实现标准协议一个独立程序（任意语言）mcp_server.py——但它是对外的插头，不是对内的插座
L3 声明式插件放文件Markdown + 清单，宿主加载我们要为 TRAE 造的就是这层
AHA 时刻 换个视角就通了：从 TRAE 看，你的 dailyreport 已经是一个 L2 插件——mcp.json 里一行 "command": ".../dailyreport-mcp"，TRAE 启动它、发现 12 个工具、按 MCP 协议调用。你早就在写「插件的代码」了，只是没人告诉你这叫插件。而 dailyreport 对内只有 L0/L1——它自己是宿主，却没有插座。

三、插件开发到底写什么代码

为 Claude Code / TRAE 这类宿主写插件，产物只有三种，只有一种含真代码：

① SKILL.md —— 纯文本，零代码

YAML frontmatter 是给宿主的「插件契约」（何时加载我），正文是给模型的「操作手册」。为 dailyreport 写的第一个真插件长这样：

---
name: dailyreport
description: 记录工作进展与查询/生成日报。Use when 用户提到「完成了某事」「记个待办」
  「生成日报」「今天做了什么」，或对话临近结束需要总结当日工作。
---
## Instructions

1. 先判意图，再选工具（MCP 服务器 ai-dailyreport）：
   - 完成 → mcp__ai-dailyreport__record_done
   - 待办 → mcp__ai-dailyreport__record_plan
   - 日报 → mcp__ai-dailyreport__generate_report
   - 查询 → mcp__ai-dailyreport__today_status / search_entries
2. 记录类调用保留用户原话，不要替用户改写事实。
3. 调用成功后，用一句话确认并附条目时间戳。
4. 禁止：未调用工具就声称「已记录」。

注意 description 的写法：前半句说「我能干什么」，Use when 说「什么时候想起我」。宿主只把这一段常驻上下文（第 1 课的渐进式披露），所以它的质量直接决定触发准确率。

② Hook 脚本 —— 唯一的「真代码」

Hooks 是宿主在固定生命周期事件（会话开始、工具调用前、提交前…）执行的 shell 命令。比如「每次新会话自动注入今日概况」：

#!/bin/bash
# session_start.sh — 复用 dailyreport 现成的 storage 模块，零 LLM 调用
cd /Users/savior/Documents/project/dailyreport
.venv/bin/python - <<'PY'
from datetime import datetime
from src import storage

today = datetime.now().strftime("%Y-%m-%d")
entries = storage.load_entries(today)
done = sum(1 for e in entries if e.get("status") == "done")
todo = sum(1 for e in entries if e.get("status") == "todo")
print(f"【dailyreport】今日已完成 {done} 条，待办 {todo} 条。")
PY

再在插件清单里把它挂到事件上：

{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command",
                     "command": "${CLAUDE_PLUGIN_ROOT}/hooks/session_start.sh" } ] }
    ]
  }
}

③ plugin.json —— 插件清单（身份证）

{
  "name": "dailyreport-harness",
  "version": "0.1.0",
  "description": "让 AI 编程工具聪明地使用 ai-dailyreport：技能触发 + 会话钩子",
  "author": { "name": "savior" }
}

最终目录就是备忘单里那个结构：plugin.json + skills/ + hooks/。第 3、4 课会带你把这三个文件真的造出来并验证触发。

易混淆 Skill 不是函数，Hook 不是回调库。Skill 是自然语言写的「条件知识」（宿主用 LLM 决定何时加载）；Hook 是确定性代码（事件到点就执行，不过 LLM）。要「聪明地判断该不该做」→ Skill；要「每次必定做」→ Hook。本课程主线里：自动记录用 Skill（需要判断意图），自动注入概况用 Hook（每次都要）。

四、方向 B：给 dailyreport 自己装插座（可选）

如果你的目标是让 dailyreport 作为宿主接受第三方扩展（比如别人给它加一个「周报生成器」插件），那就是经典的 Python 插件模式——发现、契约、加载三件套，骨架大约 30 行：

# plugins/base.py —— 契约：所有插件实现这个协议
class ReportPlugin(Protocol):
    name: str
    def render(self, entries: list[dict]) -> str: ...

# plugins/loader.py —— 发现 + 加载：扫目录、import、注册
def load_plugins(dir_path: Path) -> dict[str, ReportPlugin]:
    registry = {}
    for py in dir_path.glob("*.py"):
        if py.name.startswith("_"):
            continue
        module = importlib.import_module(f"plugins.{py.stem}")
        for _, obj in inspect.getmembers(module, inspect.isclass):
            if issubclass(obj, ReportPlugin) and obj is not ReportPlugin:
                registry[obj.name] = obj()
    return registry

但按 MISSION，当前主线是方向 A（TRAE 集成）——dailyreport 保持 L2 插件身份即可，给它自己装插座是「架构升级」方向的事，先记下不展开。
